> 版本：v1.1

## 1. 项目背景与目标

基于 Flowable 最新版本开发一个完整的工作流系统，包含前后端应用。系统需提供工作流设计、表单设计、流程执行引擎三大核心能力，并能方便地集成到其他业务系统中。

---

## 2. 技术栈

| 层级 | 技术 |
|---|---|
| 后端 | Spring Boot + Flowable |
| 前端 | Vue 3 + Element Plus |
| 数据库 | MySQL |
| 构建 | Maven（多模块）|

## 3. 功能需求

### 3.1 流程设计器

用户在浏览器中通过拖拽方式设计 BPMN 2.0 流程图。

- 支持 BPMN 2.0 规范的主流元素：开始/结束事件、用户任务、网关、子流程、泳道等
- 支持节点属性配置，各节点类型属性如下：

  **开始事件：** 名称、关联表单、发起人权限

  **用户任务（核心）：**
  - 基本信息：名称、描述
  - 审批人设置：审批人类型（指定用户/指定角色/部门负责人/发起人自选/表达式）、审批人值、多人审批方式（会签/或签）
  - 表单：关联表单、表单字段权限
  - 时限：超时时间、超时动作（提醒/升级）
  - 操作：允许驳回、允许加签、允许转签

  **网关（排他/并行/包含）：** 名称、默认流转

  **定时器事件：** 定时类型（固定时长/指定时间/重复周期）、定时值

  **子流程：** 名称、调用的流程、传入/返回变量映射

  **结束事件：** 名称

  **连线：** 条件表达式、默认流转标记、描述
- 支持连线条件编辑
- 支持导入/导出 BPMN XML
- 支持流程模拟预览(没实现
- 支持撤销/重做
- 流程定义支持分类管理
- 支持基于已有流程定义复制创建新流程
- 流程设计器应呈现现代美观的视觉风格

#### 3.1.1 后端业务逻辑配置

流程节点应支持配置后端业务逻辑，在节点进入或完成时自动执行。支持三种方式：

- **调用外部 API**：配置 HTTP 请求调用外部系统接口，支持请求参数引用流程变量、返回值写入流程变量、异常处理策略（忽略继续/中断流程）
- **调用本系统服务**：选择已注册的 Spring Bean 和方法，支持流程变量与方法参数的映射
- **执行脚本**：编写 Groovy/JavaScript 代码片段在引擎中执行

后端逻辑可在用户任务、开始事件、结束事件等节点上配置，支持在一个节点上配置多个逻辑按顺序执行。

### 3.2 表单设计器

用户在浏览器中通过拖拽方式构建表单。

#### 3.2.1 组件类型

**核心组件：**
- 单行文本、多行文本、数字输入
- 下拉选择（单选/多选）
- 单选、多选
- 日期、日期范围
- 文件上传

**扩展组件：**
- 人员选择、部门选择
- 数据引用组件（从其他业务表或表单选取数据）
- 子表/表格（动态行、多列字段）
- 嵌套表单
- 分组容器、分割线
- 自动编号、富文本、开关、评分、地址

#### 3.2.2 组件扩展

- 支持开发者注册自定义组件，无需修改核心代码
- 前后端扩展机制对称

#### 3.2.3 属性配置

- 每个组件的可配置属性按组件类型动态展示
- 包括基本属性、校验规则、高级属性

#### 3.2.4 事件脚本

- 组件支持在前端执行 JavaScript 脚本
- 脚本事件包括：初始化、值变化、失去焦点、可见性变化
- 脚本可控制其他字段的值、显隐、必填、禁用等
- 脚本在沙箱中安全执行

#### 3.2.5 可视化规则

- 常用联动场景（显隐、计算、选项过滤）提供可视化配置
- 复杂场景通过 JS 脚本兜底

#### 3.2.6 表单字段权限

- 第一期：字段区分为"创建时填写"和"审批时查看"
- 后续：细粒度角色控制

### 3.3 流程执行引擎

#### 3.3.1 基础能力

- ✅ 流程定义部署、激活、挂起
- ✅ 流程实例启动、挂起、恢复、终止
- ✅ 任务签收、完成、转办、委派
- ✅ 流程变量管理
- ✅ 流程图高亮跟踪

> **实现状态（2026-08-03）：**
> - 转办：`TransferService` + `POST /api/v1/tasks/{id}/transfer`，记录审计到 `wf_task_transfer` 表
> - 流程变量管理：`ProcessVariableService` + `ProcessVariableController`（6 个 endpoint：GET/PUT/DELETE 实例级变量 + PUT 任务级变量）
> - 流程图高亮：`ProcessHighlightService` + `GET /api/v1/process-instances/{id}/highlight`，返回已完成节点 + 当前活动节点
> - 任务完成返回值：`completeTaskWithResponse` 返回 `CompleteTaskResponse`（含下一个任务 ID/名称/办理人、流程是否结束标志）

#### 3.3.2 会签与或签

- ✅ 会签：多个审批人全部通过才通过
- ✅ 或签：任一审批人通过即通过

> **实现状态（2026-08-03）：**
> - `MultiInstanceBpmnRewriter`：部署时自动将 `multiInstanceType=parallel/sequential` 的用户任务改写为 Flowable 原生 MI 节点
> - 会签（parallel）：`collection` + `assigneeList` 变量驱动，全部完成才流转
> - 或签（sequential + completionCondition）：任一完成即结束 MI，剩余任务自动取消
> - Spike 测试验证：Spike-1 会签、Spike-2 或签

#### 3.3.3 加签与转签

- ✅ 加签：审批人临时增加其他审批人
- ✅ 转签：审批人将审批权转给他人

> **实现状态（2026-08-04）：**
> - 加签：`AddSignService` + `POST /api/v1/tasks/{id}/add-sign`，基于 `RuntimeService.addMultiInstanceExecution` 实现，支持批量加签多人
> - 转签：`ForwardSignService` + `POST /api/v1/tasks/{id}/forward-sign`，基于 `deleteMultiInstanceExecution` + `addMultiInstanceExecution` 实现，MI 实例级别人员变更
> - 委派：`POST /api/v1/tasks/{id}/delegate`，基于 `TaskService.delegateTask`，被委派人 resolve 后任务回到原办理人
> - Spike 测试验证：Spike-6 加签、Spike-7 转签

#### 3.3.4 驳回

- ✅ 第一期：驳回到发起人，发起人修改后重新提交
- 后续：驳回到任意历史节点

> **实现状态（2026-08-03）：**
> - `InitiatorNodeResolver`：解析流程定义中第一个 userTask 作为发起人节点
> - `RejectService`：基于 Flowable `changeActivityStateBuilder` 实现驳回到发起人
> - `POST /api/v1/tasks/{id}/reject`：接收 userId + reason，执行驳回
> - 集成测试验证：EndToEndIntegrationTest 完整验证 驳回→重提交 全流程

#### 3.3.5 催办

- 发起人可手动催办当前审批人
- 同任务有催办频率限制

#### 3.3.6 超时处理

- 可配置超时规则
- 超时后自动发送提醒
- 支持超时升级（转给上级或指定人）

### 3.4 REST API

系统通过 REST API 对外提供能力，供其他业务系统集成。

#### 核心 API 分组

| 分组 | 说明 |
|---|---|
| 流程定义 | 流程的 CRUD、部署、版本管理 |
| 流程实例 | 启动、终止、挂起/恢复、高亮图 |
| 任务 | 待办/已办、审批、转办、委派、催办 |
| 表单定义 | 表单 CRUD、发布 |
| 表单实例 | 表单数据提交、查询 |
| 数据源 | 通用数据查询接口 |
| 通知 | 站内信查询、已读 |
| 身份认证 | 登录、JWT |
| 用户/组织 | 用户、角色、部门 |
| 系统管理 | 租户管理、审计日志 |
| 统计 | 流程统计、任务效率 |

### 3.5 多租户

- 系统需支持多租户，不同租户间的流程数据相互隔离
- 租户信息通过请求头传递

### 3.6 用户权限与组织架构

#### 3.6.1 角色体系

| 角色 | 范围 | 职责 |
|---|---|---|
| 超级管理员 | 平台级 | 管理所有租户 |
| 租户管理员 | 租户级 | 管理本租户用户/角色 |
| 流程设计者 | 租户级 | 设计流程和表单 |
| 普通用户 | 租户级 | 发起流程、处理任务 |

#### 3.6.2 用户/组织对接

- 第一期：系统内置用户、部门、角色管理
- 后续：业务系统通过回调接口提供用户/组织数据，系统预留对接接口

### 3.7 通知

- 系统内置站内信通知中心
- 通知场景：新任务、催办、超时、超时升级、审批结果、加签
- 通知模板可配置
- 预留外部通知渠道接口（邮件、企微、钉钉等）

### 3.8 审计日志

- 记录所有关键操作：流程/表单的创建、编辑、删除、部署/发布、流程实例操作、任务操作、系统管理操作
- 支持按租户、操作人、操作类型、时间范围查询

### 3.9 统计与监控

- 第一期：基础统计（流程热度、任务效率、个人绩效、实时概览）
- 后续：SLA 监控、瓶颈分析、趋势分析、可视化仪表盘

### 3.10 流程版本管理

- 同一流程多次部署自动递增版本号
- 运行中的实例不受新版本影响
- 支持版本回滚

### 3.11 流程中心

面向普通用户的流程发起入口，用户浏览已部署、已激活的流程定义并发起新的流程实例。流程设计者、租户管理员同样可使用此入口。

#### 3.11.1 流程列表展示

- 流程按**流程分类**（对应 3.1 流程定义分类管理）分组展示
- 每个分类为一个折叠区块，默认展开第一个分类，其余折叠
- 分类内流程以卡片形式展示，每张卡片包含：流程名称、流程图标（流程定义可配置，未配置时显示分类默认图标）、简短描述（流程定义的 description 字段）、版本号、"发起"按钮
- 流程定义状态为"已挂起"的不展示
- 流程定义配置了"发起人权限"的（3.1 开始事件属性），仅对有权限的用户展示

#### 3.11.2 搜索与筛选

- 顶部提供流程名称搜索框，跨分类模糊匹配
- 搜索时所有分类自动展开，高亮匹配项
- 无可发起流程时显示空状态提示

#### 3.11.3 发起流程

- 用户点击流程卡片上的"发起"按钮 → 跳转到独立发起页面
- 发起页面内容：
  - **流程基本信息区**：流程名称、流程编号（提交后生成）、版本号、分类、流程描述
  - **流程图预览区**（可折叠，默认折叠）：展示流程定义的 BPMN 图
  - **发起表单区**：渲染流程关联的表单（3.2 表单设计器产出），表单字段权限按"创建时填写"控制（3.2.6）
  - **操作区**：提交、取消（返回流程中心）
- 提交校验：表单必填字段校验、表单事件脚本校验（3.2.4）
- 提交成功后：跳转到待办中心"我发起的"Tab，高亮显示新建的流程实例；触发通知（3.7 新任务通知给第一个审批人）
- 无关联表单的流程：直接展示流程信息 + 确认发起按钮

### 3.12 待办中心

面向普通用户的任务处理与流程跟踪入口，包含待办、已办、我发起的三个 Tab。所有租户内角色均可使用，区别只在数据范围（仅看到自己的待办/已办/发起记录）。

#### 3.12.1 待办 Tab

**列表展示：**
- 表格形式，默认按接收时间倒序
- 列：流程名称、流程编号、发起人、当前节点名称、接收时间、操作（"处理"按钮）
- 未读任务加粗显示，有催办标记的任务显示催办角标

**筛选维度：**
- 流程名称：模糊搜索
- 发起人：用户选择器
- 接收时间：日期范围选择器

**任务处理：**
- 点击"处理" → 跳转到任务处理详情页
- 详情页布局（标准三段）：
  - **顶部 — 流程基本信息**：流程名称、流程编号、发起人、发起时间、当前节点名称
  - **中部 — 审批表单**：若当前任务关联表单，渲染表单（3.2），字段权限按"审批时查看"控制（3.2.6）；展示流程变量（已填写的发起表单数据，只读）
  - **底部 — 审批意见区**：审批意见输入框（必填可配置）；主操作按钮"通过""驳回"；"更多操作"下拉菜单含转办、委派、加签、转签
  - **右侧（或可折叠抽屉）— 流程跟踪**：流程图高亮当前节点（3.3.1）；审批记录时间线（节点名称、办理人、处理时间、审批意见、操作类型）

**操作行为：**
- **通过**：校验表单 → 提交 → 返回待办列表，任务从待办移除
- **驳回**：弹出确认框填写驳回原因 → 驳回到发起人（3.3.4）→ 返回待办列表
- **转办**：弹出用户选择器选择办理人 → 转办（3.3.1）
- **委派**：弹出用户选择器选择被委派人 → 委派（3.3.3）
- **加签**：弹出用户选择器（多选）→ 加签（3.3.3）
- **转签**：弹出用户选择器选择新审批人 → 转签（3.3.3）
- 操作完成后返回待办列表，触发对应通知（3.7）

#### 3.12.2 已办 Tab

**列表展示：**
- 表格形式，默认按处理时间倒序
- 列：流程名称、流程编号、发起人、节点名称、处理时间、审批结果（通过/驳回/转办等）、操作（"查看"按钮）

**筛选维度：**
- 流程名称：模糊搜索
- 发起人：用户选择器
- 处理时间：日期范围选择器
- 审批结果：下拉（全部/通过/驳回/转办/委派/加签/转签）

**查看详情：**
- 点击"查看" → 跳转到只读详情页
- 展示内容同待办详情页，但：审批表单只读、无操作按钮、流程跟踪显示提交时的处理记录（高亮当时处理的节点）
- 若流程实例仍在进行中，流程跟踪显示最新状态（可跳转查看实时进度）

#### 3.12.3 我发起的 Tab

**列表展示：**
- 表格形式，默认按发起时间倒序
- 列：流程名称、流程编号、当前节点、发起时间、状态（进行中/已通过/已驳回/已终止）、操作（"跟踪"按钮）

**筛选维度：**
- 流程名称：模糊搜索
- 发起时间：日期范围选择器
- 状态：下拉（全部/进行中/已通过/已驳回/已终止）

**流程跟踪：**
- 点击"跟踪" → 跳转到流程实例详情页
- 展示内容：流程基本信息、流程图高亮当前活动节点（3.3.1）、完整审批记录时间线
- 进行中的实例：可执行催办（3.3.5），对当前待办审批人发起催办，受催办频率限制
- 已结束的实例：只读展示完整流程记录
- 若流程被驳回回到发起人（3.3.4），该实例出现在"待办"Tab 而非此处，状态仍为"进行中"

#### 3.12.4 分页

三个 Tab 的列表均支持分页，默认每页 20 条。

## 5. 分阶段计划

### 第一阶段：核心框架 + 引擎集成

搭建项目骨架，集成 Flowable 引擎，实现基础 REST API，跑通流程全链路。

### 第二阶段：搭建前端UI框架

搭建项目前端框架，实现一些通用的前端框架组件

### 第三阶段：管理后台 UI

实现 Vue 3 前端，包括流程管理、任务管理、流程跟踪、用户登录、通知中心、审计日志。

### 第三阶段补充：流程中心与待办中心

在第三阶段同步实现面向普通用户的两个核心入口：

- **流程中心**（3.11）：分类分组展示已部署流程、发起流程页面（含表单填写与流程图预览）
- **待办中心**（3.12）：待办/已办/我发起的三个 Tab，任务处理详情页（含审批操作、转办/委派/加签/转签、流程跟踪图、审批记录时间线）

### 第四阶段：BPMN 设计器

实现浏览器端拖拽式流程设计器，支持流程设计、保存、部署、模拟。

### 第五阶段：表单设计器

实现拖拽式表单设计器，支持表单与流程变量打通。

### 后续阶段

| 功能 | 优先级 |
|---|---|
| 扩展表单组件（人员选择、数据引用、子表等） | 高 |
| 驳回任意节点 | 高 |
| 邮件/企微/钉钉通知 | 中 |
| SLA 监控/仪表盘 | 中 |
| 表单字段细粒度权限 | 中 |
| 版本对比视图 | 低 |
| K8s 部署 | 低 |
| 国际化 | 低 |
