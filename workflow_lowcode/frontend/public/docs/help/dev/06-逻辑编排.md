# 06 逻辑编排

逻辑流是拖节点拼出来的服务端自动化流程：调外部接口、读写业务数据、发通知、调 AI。入口：**开发管理 → 逻辑流**。

## 6.1 状态与常见应用场景

逻辑流状态：`草稿 → 已发布`。只有已发布的逻辑流才能被绑定/被其他流程调用。列表页可对单条流程「运行测试」（填入参、看每个节点的输出），也可导入 JSON 构造测试实例。

**常见应用场景**：

| 场景 | 用的节点 | 触发方式 |
| --- | --- | --- |
| **提交前校验/补全**：提交时查重、按规则补全编号，不通过则拦截 | 数据查询 → 条件 | 表单事件的「前」触发点（失败即拒绝提交） |
| **提交后联动落表**：订单提交后扣库存、生成跟进任务、发站内通知 | 数据查询 → 数据更新/新增 → 消息通知 | 表单事件的「后」触发点（可选同事务回滚） |
| **外部系统同步**：拉外部接口数据清洗后幂等落表；或本平台数据变更后推送出去 | HTTP → 数据映射 → 数据写入（upsert）；或 数据查询 → HTTP | 表单事件 / 手动运行 |
| **审批自动化**：审批通过后自动写台账、通知相关人、回写业务系统 | 数据新增/更新 → 消息通知 → HTTP | 流程事件（节点/审批通过时点） |
| **数据加工汇总**：跨表查询、按分组聚合、把结果写回汇总表；也常用「运行测试」做临时批量修数 | 数据查询 → 聚合 → 数据更新 | 手动运行 / 表单事件 |
| **AI 智能处理**：对提交内容做分类、摘要或审核建议，按结果走不同分支 | AI 大模型 → 条件 | 表单事件 / 流程事件 |

## 6.2 节点面板

![逻辑流设计器：左侧节点面板 + 画布](images/logicflow-designer.png)

四个分组，选中节点后在右侧属性面板配置。下面每个节点先给**常见应用场景**，再列关键配置。

### 控制节点

**开始 / 结束**：流程起点与终点，本身不承载业务。开始节点声明**输入参数**（名称 + 类型）——被表单事件绑定时，参数必须与触发点事件参数完全一致，可用「输入参数」对话框的「导入触发点参数」一键生成。

**条件**：
*场景*——提交前查重（查到的行数 > 0 走「拒绝」出边）；库存低于安全线走补货分支；按 AI 分类结果决定后续动作。

配置：多条件**且/或**组合；每条 = 判断变量 + 运算符（等于/不等于/大于/包含/为空/不为空等）+ 比较值（字面量或 `{{var}}`，「为空/不为空」无需比较值）；命中走「真」出边，否则走「假」。

**多路分支**：
*场景*——按单据类型分处理链（差旅/采购/付款各自落表逻辑）；按外部接口返回的状态码走不同后续。

配置：按**分支变量**的值逐个匹配 case（匹配值为字面量或 `{{var}}`，数值优先比对），命中走该 case 出边（出边标签即匹配值），全不中走默认出边。

**延时**：
*场景*——错峰调用限流的外部接口；等外部系统处理完再查结果。

配置：同步等待 1~60000 毫秒；逻辑流在请求线程内执行，超过一分钟的等待请改用外部调度方案。

### 动作节点

**HTTP 调用**：
*场景*——拉取第三方系统数据（配合数据写入做同步）；业务变更后推送 webhook 通知下游；调用内部微服务。

配置：请求 URL（支持 `{{var}}`）+ 方法；Headers 键值对；Query / Body 参数按「左=流变量名，右=接口参数名」映射；连接超时默认 3000ms、读取超时默认 5000ms；响应写回上下文变量供下游引用。

**Bean 方法**：
*场景*——复用后端已有的业务方法（生成单号、结算计算等），不用在脚本里重写；调用平台预置能力。

配置：调用后端 Spring 容器注册的服务方法。Bean 名称支持搜索选择（清单加载失败降级为手输），方法名随 Bean 联动加载；参数同样「左=流变量，右=方法形参」按序注入。方法清单由平台开发预置维护。

**Groovy 脚本**：
*场景*——数据清洗与格式转换；复杂计算（费用分摊、佣金提成）；把多个上游变量拼装成一个结构再交给数据节点。

配置：服务端沙箱执行。上下文变量直接按名访问；末行用 Map 字面量 `[key: value]` 返回多输出；用 `beans.<bean名>.<方法名>(参数…)` 调用白名单 Bean（与 Bean 节点同一白名单，参数个数需匹配），输入 `beans.` 会自动提示。

**批处理**：
*场景*——对查询出的订单列表逐条调外部接口同步；给一批人逐个发通知；批量修数的循环体。

配置：遍历集合逐项执行。集合表达式填 `{{listVar}}` 或 JSON 数组字面量；项变量默认 `item`、序号默认 `index`（可改名）；**循环体在画布上配置**——把动作节点拖到批处理节点右侧的循环虚线上，多项按链序执行，拖离虚线即移出循环；单次最大迭代数有硬上限 1000；单项失败策略二选一：任一项失败即中断整批，或记录该项失败后继续。各轮输出聚合为列表。

**子流程**：
*场景*——多条主流程共用的「扣库存」「发通知」逻辑抽成一条子流，改一处处处生效；把超长主流程拆段，画布好读、问题好定位。

配置：调用另一条**已发布**逻辑流，其输出写回本流变量。「继承上下文」开=父流全部变量传入子流，关=仅传映射变量；变量映射可做覆盖/改名；嵌套上限 5 层，递归/自引用会被引擎拒绝。

**消息通知**：
*场景*——提交后通知负责人接单；审批结果出来后回告发起人；异常数据公告。

配置：按消息模板发送。填模板代码（须已存在，必填变量缺失会被拒绝）、接收人 ID（上限 20 人，支持 `{{var}}`）、模板变量对；消息类型 PRIVATE（私信，默认）/ PUBLIC（广播）/ SYSTEM（公告）；渠道 IN_APP（站内信，默认）/ SMS（模板须有对应渠道配置）。模板与渠道在「消息管理」维护（见管理手册 04）。

### 数据节点

**数据查询**：
*场景*——提交前查重；取主数据做联动计算（查客户信用额度再算可用余额）；聚合统计前的取数。

配置：目标选**业务表单**（自动租户隔离、必填校验、JSON 列、日期归一）或**其他数据表**（表含 tenant_id 列时自动租户过滤）。筛选多条件 AND，值支持 `{{var}}`、表达式（四则运算与 ROUND/ABS/IFNULL）、`#` 呼出目标表字段；可选关键字 + 关键字列做模糊匹配；行数上限 1~100（默认 50）。输出 `{total, rows}`，rows 行含 id 与全部业务列，下游取 `rows[0].字段`。

**数据新增**：
*场景*——订单提交后自动生成一条跟进任务；写操作日志/审计表。

配置：向业务表单/数据表插一行。字段值支持 `{{var}}`（保留原始类型）、表达式、单引号字符串字面量；业务表单托管列（主键/租户/版本/审计）自动生成。输出含 id 的新行。

**数据更新**：
*场景*——扣库存（`stockQty - {{formData.qty}}`）；单据状态流转；多张关联表在同一个事务里一起改。

配置：纯配置更新，一个节点可配**多张目标表**——多表在单事务内按顺序执行，全成提交、任一失败整体回滚（全有或全无）；需要逐表独立失败语义就拆成多个节点。SET 直接赋值，值支持表达式（如 `stockQty - {{formData.qty}}`）；WHERE 多条件 AND，**条件为空会影响全表**，务必谨慎。未声明输出时写入受影响行数。

**数据写入（upsert）**：
*场景*——外部系统数据定时拉入，反复跑不产生重复行；按业务编号（如手机号、单号）「有则改无则建」。

配置：向业务表单按唯一字段「有则更新、无则新增」，原子 SQL 无竞态。冲突键从表单中标记「唯一」的业务字段里选（发布表单时平台已自动建 `(tenant_id, 字段)` 复合唯一索引，运行期还会实查索引兜底）；写入字段必须包含冲突键列；「更新时覆盖」可配仅更新路径才刷新的列（如 updated_by、最近同步时间）。输出 created/updated/unchanged 与记录 id。

**数据删除**：
*场景*——作废草稿数据；按条件清理临时表。

配置：两种方式——按 ID 精确删一行（**级联子表**，行不存在报错）；按条件批量删（**不级联**子表；至少一个带值条件防全表删除；自动追加租户过滤防跨租户误删）。

**SQL 批处理**：
*场景*——跨多表的复杂加工（数据节点拼不出来的 JOIN/窗口逻辑）；一次性批量修数/对账。

配置：多条 SQL 用 `;` 分隔顺序执行。`{{var.path}}` 编译为 JDBC `?` 参数绑定防注入（数值类型保留）；`-- name: 别名` 注释可给语句命名输出键；FROM/JOIN/UPDATE 等位置自动提示表名和字段名；仅支持 DML（SELECT/INSERT/UPDATE/DELETE/REPLACE 及 SHOW/DESC/EXPLAIN/WITH），**DDL 会破坏事务故不支持**。失败策略：失败回滚（单事务整体回滚，节点不抛错，下游可按 failed/aborted 变量分支）或逐条继续（失败记入该条目继续执行）。单条 SELECT 最多返回 1~1000 行，超出截断并标记 truncated。

**数据映射**：
*场景*——按第三方接口的报文结构组装请求体；把多个变量拼成一条通知/消息内容。

配置：用 JSON 模板 + `{{var.path}}` 组装新对象。值位占位符注入变量**原始值**（对象/数组/数值保留；Long 按平台约定转字符串防 JS 精度丢失）；字符串内占位符做文本插值（如 `"共 {{total}} 条"`）；变量缺失时值位注入 null、插值为空串。

**聚合**：
*场景*——把当月订单按客户分组汇总金额，写回客户汇总表；统计某状态下单据数量。

配置：对集合变量（如上游查询的 `{{dq_x1.rows}}`）做 SUM/AVG/MIN/MAX/COUNT，可多选算子；可选分组字段，按字段值分组后逐组聚合，输出 `[{group, count, sum, …}]`；纯 COUNT 可不填聚合字段。

### 智能节点

**AI 大模型**：
*场景*——对提交内容自动分类后交给多路分支；生成工单摘要给审批人参考；内容合规审核建议。

配置：调用平台接入的大模型。用户提示词与系统提示词（角色/输出约束）都支持 `{{var}}`；温度 0~2（分类/抽取类建议 ≤0.3，越大越发散），留空用平台默认。模型端点/API Key/模型名在「系统管理 → 模型配置」统一设置，此处无需填写（见管理手册 06）。

## 6.3 变量与代码提示

节点输出会写入上下文变量，下游任何输入框引用这些变量；连线传值、批处理循环项（逐条数据）同理。取不到值多半是变量名或路径写错——用运行测试逐节点核对输出。

变量输入不是普通文本框，而是全项目共用的 CodeMirror 代码编辑器，**边写边提示、不用背变量名**：

![输入 {{ 触发变量自动补全](images/logic-var-mention.png)

上图为数据更新节点 SET 值里输入 `{{` 后的自动补全浮层：候选列出当前上下文全部可用变量（含 `formData.*` 表单字段），↑↓ 移动、Enter 选中即自动补全为 `{{变量名}}` 占位符并高亮；继续输入按前缀过滤。

各输入框的提示方式汇总：

| 输入位置 | 怎么提示 |
| --- | --- |
| 节点参数 / SET 值 / 提示词等大多数输入框 | 输入 `{{` 弹出变量候选列表；选中插入占位符 |
| 数据查询筛选值、数据更新 WHERE 值 | 输入 `#` 呼出**目标表字段**列表（补全为 `{{formData.字段}}`） |
| 数据更新的值表达式 | 整框表达式语义（ƒx 角标），直接写 `stockQty - {{formData.qty}}`，字段名即输即补 |
| Groovy 脚本 | 变量按名直接访问（即输即补）；输入 `beans.` 自动提示白名单 Bean 与方法 |
| SQL 批处理 | FROM/JOIN/UPDATE 处自动提示表名和字段名；`{{var}}` 模板补全 |
| 所有变量输入框 | 编辑器右侧有**变量按钮**，点开从列表选、插入到光标处——记不清变量名时用它 |

另外两种取值习惯：字段值下拉/候选来自上游节点输出（如数据查询的 `rows[0].字段`），建议一律从候选选；手打路径拼错不会报错、只会静默取空。

## 6.4 逻辑流被谁触发

1. **表单事件绑定**：表单列表每行有「逻辑流绑定」入口。触发点为数据保存/更新/删除的前、后共六类，另有 AFTER_SNAPSHOT（流程快照类事件，视表单接入流程的情况出现）。
   - **前类触发点 = 校验语义**：逻辑流失败会拒绝本次操作（如提交前查重、补全编号）；
   - **后类触发点**：可选「同事务回滚」（强一致，失败连带业务操作回滚）或「提交后执行」（失败只留运行历史，不影响已提交数据）；
   - 绑定下拉只显示**已发布且入参声明与触发点事件参数完全一致**的逻辑流；不匹配时，在逻辑流设计器的「输入参数」对话框一键导入该触发点参数再发布。
2. **流程事件**：工作流的节点/事件可触发逻辑流（服务任务、审批通过等时点），用于审批后的自动落表、通知、外呼。
3. **手动运行**：列表页「运行测试」，兼作调试与临时批量修数入口。

## 6.5 设计建议

- 一条逻辑流只做一件事，复杂场景用「子流程」组合，方便复用和定位问题；
- 校验放「前」触发点，联动写数据放「后」触发点，事务边界按上节语义选；
- 涉及多表一致性优先用「数据更新（多表事务）」而非拆成多个节点；
- 需要幂等的同步写入（外部数据反复拉）用「数据写入（upsert）」，别用「新增 + 先查后判」；
- 批处理量大时设置分批与节流（单次最大迭代数、单项失败策略），避免压垮下游接口。

## 6.6 常见问题

**Q：绑定弹窗里找不到我的逻辑流？**
两个原因：未发布；或入参声明与触发点不一致。打开设计器「输入参数」，用「导入触发点参数」按钮生成声明后重新发布。

**Q：HTTP 节点调本地开发的后端接口不通？**
确认逻辑流运行在后端服务内，URL 用后端实际监听地址（默认 8080），不要用浏览器里的 3000 前端地址。

**Q：Groovy 脚本和 SQL 批处理该选哪个？**
纯数据操作优先数据节点/SQL 批处理（有租户隔离与参数绑定保护）；确有复杂算法再上 Groovy，并注意脚本在服务端执行，谨慎处理外部输入。

**Q：数据更新把整表都改了？**
WHERE 条件为空（或全部条件没填值）时会更新全表。配置时确认每张目标表至少有一个确定的条件；拿不准先在「运行测试」里跑一遍看输出行数。
