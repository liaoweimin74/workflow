## Design Summary

数据表格（PageDataTable）和数据容器（formContainer）组件联动功能，支持事件流驱动的记录加载、编辑和保存。

### 核心功能
1. **表格-容器联动**：点击表格的编辑/查看按钮或行点击，formContainer加载对应记录
2. **记录编辑与保存**：编辑完成后保存，调用数据源保存接口，操作异常提示用户
3. **多种显示形式**：支持弹出窗口（默认）、新开页签、页面内嵌
4. **按钮自定义**：默认按钮（新增、取消、确定、删除、复制）+ 自定义按钮
5. **事件流配置**：支持设计器可视化配置 + JSON高级配置
6. **智能数据同步**：保存后智能同步表格中的对应行

## Alternatives Considered

### 方案 A：扩展DsActionBus事件流（推荐）
- **做法**：扩展现有的DsActionBus事件总线，增加表格-容器联动的专用事件和动作
- **优点**：
  - 复用现有事件总线架构
  - 配置灵活，支持可视化+JSON
  - 易于扩展其他联动场景
- **缺点**：
  - 需要扩展现有DsActionBus
  - 事件流配置较复杂
- **为何未采用**：这是推荐方案，已被采用

### 方案 B：独立联动管理器
- **做法**：创建独立的联动管理器，专门处理表格-容器联动
- **优点**：
  - 职责清晰，独立性强
  - 易于测试和维护
  - 不影响现有事件总线
- **缺点**：
  - 需要新建独立模块
  - 与现有事件总线并行，可能有重复
- **为何未采用**：与现有架构并行，增加维护成本

### 方案 C：增强formContainer组件
- **做法**：直接增强formContainer组件，内置表格联动能力
- **优点**：
  - 使用简单，调用直观
  - 内聚性好，功能自包含
- **缺点**：
  - 与表格耦合较紧
  - 扩展性较差
- **为何未采用**：耦合度高，不利于未来扩展

## Agreed Approach

**采用方案 A：扩展DsActionBus事件流**

**理由**：
1. **复用现有架构**：DsActionBus已经在PageRendererPage中使用，扩展它最自然
2. **配置灵活**：支持可视化配置和JSON高级配置
3. **事件驱动**：符合用户要求的"事件流"方式
4. **易于扩展**：未来可以支持更多联动场景

## Key Decisions

1. **事件类型扩展**：
   - `row-edit`：行编辑触发
   - `row-view`：行查看触发
   - `row-create`：新增触发

2. **动作类型扩展**：
   - `open-container`：打开formContainer（支持displayMode参数）
   - `load-record`：加载记录到formContainer
   - `save-container`：保存formContainer数据
   - `close-container`：关闭formContainer

3. **显示形式配置**：
   - 默认：弹出窗口
   - 支持：弹出窗口、新开页签、页面内嵌
   - 配置方式：默认配置+事件覆盖

4. **按钮配置**：
   - 默认按钮：新增、取消、确定、删除（默认隐藏）、复制（默认隐藏）
   - 支持自定义按钮和事件链

5. **数据同步**：
   - 保存后智能同步表格中的对应行
