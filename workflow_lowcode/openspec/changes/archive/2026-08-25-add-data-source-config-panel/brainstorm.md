## Design Summary

创建通用的数据源配置面板组件 `DataSourceConfigPanel.vue`，让所有设计器（页面设计器、表单设计器等）都能使用统一的页面数据源配置功能。当前只有页面设计器有数据源配置功能，其他设计器缺乏这个能力。

## Alternatives Considered

### 方案 A：增加通用数据源配置组件（推荐）
- **做法**：创建 `DataSourceConfigPanel.vue` 组件，提供统一的数据源绑定配置界面
- **优点**：
  - 统一性：所有设计器使用相同的配置组件
  - 复用性：避免重复开发
  - 维护性：集中管理数据源配置逻辑
  - 用户体验：一致的配置界面
- **缺点**：
  - 需要开发一个新的组件
  - 需要重构现有设计器以使用新组件
- **为何未采用**：这是推荐方案

### 方案 B：保持现有架构，优化UI/UX
- **做法**：保持现有架构，只优化页面设计器中的数据源配置UI/UX
- **优点**：
  - 最小改动，风险低
  - 不需要开发新组件
- **缺点**：
  - 无法解决其他设计器缺乏数据源配置功能的问题
  - 配置逻辑分散，维护成本高
- **为何未采用**：无法解决核心问题——其他设计器缺乏数据源配置能力

### 方案 C：统一数据源管理
- **做法**：将数据源配置统一到一个独立的管理界面
- **优点**：
  - 集中管理，一致性好
  - 可以提供更强大的数据源管理功能
- **缺点**：
  - 需要较大的架构调整
  - 可能影响现有工作流
- **为何未采用**：改动过大，不符合当前需求

## Agreed Approach

采用方案 A：增加通用数据源配置组件。理由如下：
1. **解决核心问题**：当前只有页面设计器有数据源配置功能，其他设计器缺乏这个能力
2. **符合YAGNI原则**：用户明确指出了"其他表单设计器里好像没有页面数据源的配置"，这是一个真实存在的需求缺口
3. **架构合理性**：保持现有的页面内数据源架构，将数据源配置能力提取为可复用组件

## Key Decisions

1. **组件名称**：`DataSourceConfigPanel.vue`
2. **组件位置**：`frontend/src/components/business/DataSourceConfigPanel.vue`
3. **核心功能**：
   - 数据源绑定：添加、编辑、删除页面内数据源绑定
   - 全局数据源选择：从已启用的全局数据源中选择绑定目标
   - 配置管理：提供数据源绑定列表的增删改查功能
4. **组件接口**：
   - Props：`dataSources`（当前数据源绑定配置）、`enabledDataSources`（已启用的全局数据源列表）
   - Emits：`update:dataSources`（更新数据源绑定配置）
5. **保持现有架构**：页面内数据源 → 全局数据源的绑定方式不变
