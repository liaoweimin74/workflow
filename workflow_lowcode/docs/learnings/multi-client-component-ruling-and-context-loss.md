# 多端组件讨论的上下文坑与应答纪律（裁决本体见 PRD 3.13）

> 本文只保留**过程经验**。多端组件形态的产品级裁决已归位需求文档：
> `docs/PRD.md` §3.13「多端客户端交付」；设计权威源 `docs/designs/2026-10-25-多端客户端-菜单组织与页面原型.md` §5。

## 一、上下文压缩会丢用户输入的"前提"（2026-10-26 事故）

- **现象**：用户早前主动提出"移动端与 WEB 端组件不一样"的约束并促成设计文档 §5 裁决；长会话 checkpoint 压缩后只剩一句结论口径，助手回答"移动端设计入口"时只报挂载路径、丢掉组件分端前提，用户再次追问后助手又当作新问题重新查证——用户输入被当成没说过。
- **对策（纪律）**：用户主动提出的架构/产品约束，**说出来的当下就落进 PRD/设计文档/decisions**，不留在会话上下文里赌压缩友好。摘要式答复必须携带结论的前提与边界。

## 二、敏感字面量被会话渲染打码污染探针文件（同日事故）

- **现象**：脚本内容里的密码在会话渲染中被打码为 `***`，照打码视图 write 落盘后文件里就是字面 `***`；探针发出错误凭据 → "登录 500 后端故障"假象，消耗了整轮重启/查库/jshell 取证。
- **对策**：验证脚本涉及凭据/密钥等敏感字面量时，一律用 `[char]` 码点拼接构造，并用布尔检查（`$c.Contains($needle)`）核对落盘文件实况；后端行为反常时先怀疑自己发出去的字节。

## 三、应答规则（长期生效）

- 回答任何"移动端/多端交付/页面设计"问题，先读 `docs/PRD.md` §3.13 与其引用的 designs §5，不得 WEB-only 假设。
- 本节由用户 2026-10-26 明示"长期记忆，不要再忘记"后立档，2026-10-26 归位重构：约束本体进 PRD，本文降级为过程经验指针。
