## Design Summary

本变更实现 **data-picker（数据引用组件）**：业务表单字段可通过可视化配置引用其他业务表单（底表）的数据记录。运行时渲染为"点击弹窗选择记录"的控件，选中后**值存被引用记录 id，冗余显示文本存关联列**。

v2 范围：仅本系统业务表单数据源（FORM），支持单选/多选、级联联动（依赖字段过滤选项）、返回字段回填。外部 API 数据源、行级权限留待后续。

核心链路：设计器可视化配置（选目标表单/显示字段/列表列/回填映射/级联依赖）→ schema 存入字段 rule props → 运行时 DataPicker 组件调 `BizDataService.query` 选值 → CRUD 时校验 id 存在性并自动维护冗余文本列 → 列表/详情通过批量解析 API 还原显示。

## Alternatives Considered

### 方案 A：存 id + 冗余显示文本（Agreed）
- **做法**：data-picker 字段映射为两列——`<key>`（VARCHAR(64)，存 id，多选逗号分隔）+ `<key>_text`（VARCHAR(1024)，冗余显示文本，自动维护）。列表/详情直接显示文本无需联查。
- **優點**：展示零联查、被引用数据删除后旧文本不红碎、回填/级联可回查 id
- **缺點**：多一列冗余、被引用方改名后旧文本不同步（可接受）
- **為何未採用**：无，此为最终方案。

### 方案 B：只存 id，渲染时联查
- **做法**：只存 id，列表/详情渲染时批量解析 API 还原文本。
- **優點**：数据最干净、无冗余。
- **缺點**：每次列表都要额外解析查询（N 条 id 一次批量查），被引用数据删除后红碎，复杂且脆弱。
- **為何未採用**：展示是最高频路径，联查成本与红碎风险不值得；冗余文本方案一次写入、永远零查询。

### 方案 C：存整行 JSON 快照
- **做法**：选中时把整行数据 JSON 存列。
- **優點**：实现最简单、展示无需查询。
- **缺點**：数据冗余严重、被引用方变更完全不同步、级联无法回查、JSON 列不可筛选，与"物理表可查"的底表理念冲突。
- **為何未採用**：冗余失控且失去引用语义（id 才是关系，JSON 是快照），后续统计/联查无从下手。

### 方案 D：数据源范围（v2 取舍）
- **做法**：
  - D-1 仅本系统业务表单（FORM）：设计器选表单即可，后端复用 BizDataService.query
  - D-2 业务表单 + 外部 API：额外配 URL/参数/响应解析
- **優點/缺點**：D-1 范围可控最快落地；D-2 能力全但安全/错误处理/解析规则复杂度高，v2 膨胀
- **為何未採用 D-2**：v2 核心价值是"表单间引用"，API 数据源独立成后续 feature 更清晰

### 方案 E：级联联动（v2 取舍）
- **做法**：E-1 v2 包含级联（依赖字段 → filter）；E-2 级联留后续
- **為何採用 E-1**：先选部门再选员工是高频场景，PRD 明确提及；实现中等复杂度（配置 dependOn + 运行时 filter），v2 纳入成本可控

## Agreed Approach

采用**方案 A（存 id + 冗余文本）**，叠加 D-1（仅业务表单数据源）、E-1（v2 包含级联）、多选支持、可视化配置弹窗。理由：展示零查询、引用语义清晰（id 关系）、复用现有 BizDataService.query 与 LookupPicker 交互雏形，v2 范围聚焦"表单间数据引用"核心价值。

## Key Decisions

1. **值存储 = id + 冗余显示文本**：`<key>` VARCHAR(64) 存 id（多选逗号分隔），`<key>_text` VARCHAR(1024) 存显示文本（自动维护）。列映射规则扩展（ColumnTypeMapper dataPicker → 两列，`_text` 标记隐藏列）。
2. **数据源 v2 = 仅本系统业务表单**：设计器配置 sourceFormKey；可选值查询复用 `BizDataService.query`（级联 filter + keyword + 分页已具备）。
3. **级联 v2 包含**：props `dependOn: { field, sourceColumn }`——运行时把依赖字段当前值作为 filter 传给目标表查询；依赖字段变化时重置当前值并刷新选项。
4. **单选 + 多选都支持**：mode=single/multiple；多选 id 与文本均逗号分隔存储。
5. **配置交互 = 可视化配置弹窗**：拖入"数据引用"组件后双击打开 DataPickerConfigDialog——选目标表单（列出已发布业务表单）→ 自动带出可引用列（column_config）→ 配显示字段/弹窗列表列/返回字段映射/级联依赖/单多选。产出 rule props 存入 schema。
6. **返回字段回填**：复用 LookupPicker 的 returnFields 机制（formCreateInject.api.setValue），选中回填、清空联动清空。
7. **批量解析 API**：`GET /api/v1/biz-data/{formKey}/resolve?ids=...` → id→显示文本映射，供列表/详情还原与回填校验。
8. **CRUD 集成**：create/update 时校验 data-picker id 存在于目标表单（BizDataHandler 内建通用校验或 Service 内置），自动生成冗余文本。
9. **展示与只读**：运行时组件只读模式显示冗余文本；`_text` 列不进管理页表格默认显示。

## Open Questions

- 多选文本分隔符：默认逗号（值内可能含逗号的显示文本如何处理）——v2 接受局限，文档标注。
- 被引用表单删除时：底表保留、引用方冗余文本保留（快照语义），不做级联删除——确认接受。
- 目标表单列变更（引用列被删）：发布时校验引用配置的列仍存在，不存在则提示重新配置——发布校验纳入 v2。
