# Spec Delta — client-scoped-role

## ADDED Requirements

### Requirement: 角色挂单一客户端
`sys_role` SHALL 增加 `client_id`（NOT NULL），每条角色记录恰好归属一个客户端；存量角色 MUST 全部回填为默认平台客户端。"平台端管理员"与"司机端管理员"是两个独立角色，不存在跨端通用角色。

#### Scenario: 同名片段不共享授权
- **WHEN** 平台端"管理员"角色与司机端"调度员"角色分别授权不同菜单
- **THEN** 两端授权互不影响，各自只在本端树内生效

### Requirement: 登录链路端一致性校验
认证/授权链路 SHALL 校验请求携带的客户端上下文与用户角色所属端一致；不一致时 MUST 按"该端无角色"处理（菜单为空 + API 403），MUST NOT 出现降级越权或误放行为。

#### Scenario: 持平台角色访问司机端
- **WHEN** 仅拥有平台端角色的用户经司机端 H5 入口登录
- **THEN** 登录本身成功但司机端菜单为空，调用司机端页面 API 返回 403

#### Scenario: 多端人员各端各授
- **WHEN** 运营人员同时被授予平台端角色与司机端角色并分别登录两端
- **THEN** 两端各按其角色呈现菜单与权限，互不串用

### Requirement: 角色管理所属端维度
角色管理页 SHALL 增加"所属端"列与筛选；新建/编辑角色时 MUST 指定所属端（缺省当前平台端）；客户端设置抽屉（A2）"注册默认角色"下拉 MUST 仅枚举本端角色。

#### Scenario: 默认角色限本端
- **WHEN** 在司机端 A2 抽屉设置"注册默认角色"
- **THEN** 下拉仅出现 client_id=司机端 的角色，无法选中平台端角色

### Requirement: 端内授权语义不变
角色在端内的授权模型（菜单勾选、按钮权限码、成员组、数据范围主体）SHALL 沿用现状语义，仅增加端归属约束；权限码 MUST NOT 添加端前缀，跨端同名权限码表示同一操作语义。

#### Scenario: 权限码跨端复用
- **WHEN** 平台端与司机端都挂接待办页并使用 `process:todo:list`
- **THEN** 权限码同码同义，各自端内独立授权判定
