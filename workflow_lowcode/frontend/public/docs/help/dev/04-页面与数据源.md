# 04 页面与数据源

页面是用户看到的界面，数据源是界面背后的取数通道。本章信息量最大，建议边开设计器边读。

## 4.1 数据源：五种取数方式

入口：**开发管理 → 数据源管理**。数据源状态机：`草稿 → 启用 / 停用`，页面组件只能消费启用状态的数据源。

![数据源列表](images/data-source-list.png)

| 类型 | 数据来源 | 可写 | 说明 |
| --- | --- | --- | --- |
| **FORM 业务表单** | 已发布业务表单的数据表 | 是 | 最常用；列取自表单 schema |
| **WORKFLOW 工作流表单** | 跨流程实例聚合的流程填报数据 | 否（只读） | 额外固定 5 个系统列：实例 ID、流程状态、发起人、发起时间、当前节点；写操作会被后端拒绝并给出中文提示；启用前校验所绑表单已发布且为工作流类型 |
| **SYSTEM 系统内建** | 平台自带结构（用户、组织等） | 视对象 | 列表上显示为「内建」，免配置直接可用 |
| **SQL** | 自定义 SQL 查询 | 否 | 提供 SQL 编辑器 + 可视化查询构建器（点选表、列、条件生成 SQL），可预览字段映射 |
| **API 第三方** | 外部 HTTP 接口 | 视接口 | 配置 URL、方法、参数与请求头，可「探测」拉取样例响应并映射字段 |

进阶能力：**表单关联（JOIN）**——在数据源上把两个表单按关联列拼成宽表（如「订单 + 客户」），关联列候选由平台按两侧字段类型给出；**数据预览**——数据源列表页可直接打开某数据源的数据浏览页，配置完先在这里核对行列，再去做页面。

## 4.2 数据源、业务表单与页面的关系

三个概念经常被混为一谈，其实各管一层：

| | 业务表单 | 数据源 | 页面 |
| --- | --- | --- | --- |
| 本质 | **数据模型**：字段 + 校验 + 布局，发布后生成物理表 | **取数通道**：把表单/流程/SQL/API 包装成统一的「列 + 行」接口 | **展示交互层**：组件 + 数据绑定 + 动作 |
| 用户直接接触？ | 通过业务数据列表页可以 | 不直接，是中间层 | 是 |
| 关心的事 | 数据怎么存、怎么校验 | 数据从哪来、列叫什么 | 数据怎么展示、点了做什么 |

**连接关系**：

```
业务表单 ──发布──▶ 物理表 wf_biz_<formKey>
    │                    ▲
    └─FORM 数据源包装─────┤（一个表单可被多个数据源包装）
                         │
页面数据源（页面内标识）──绑定──▶ 全局数据源
    │
组件（表格/卡片/容器…）──选「页面内标识」──▶ 取数、渲染、动作
```

- **一个表单可以被多个数据源包装**：比如同一张客户表，建「全部客户」「启用客户」两个数据源，给不同页面用；
- **一个页面可以绑多个数据源**：设计器工具栏「数据源配置 (4)」表示当前页面绑了 4 个；
- **改动传导是单向的**：表单加字段 → 数据源列自动跟上 → 页面里重新勾选展示列即可见，三处不用重复定义字段；
- **页面也可以不绑表单**：SQL/API 数据源的页面不涉及任何表单；反过来表单也可以完全不经页面使用（直接用业务数据列表录入）。

一句话记忆：**表单管存、数据源管取、页面管看**。

## 4.3 页面生命周期

入口：**开发管理 → 页面列表**（含「页面 / 模板」两个 Tab）。

![页面列表](images/page-list.png)

1. **新建页面**：填名称与标识 key。绑定表单是可选项——自定义页面主要靠数据源取数，也可按需绑定已发布表单（用于表单容器录入）。
2. **设计**：进入页面设计器搭组件（见 [4.4~4.8](#4.4)）。
3. **发布**：草稿状态可反复编辑；发布后用户可访问。
4. **挂接菜单**：已发布页面一键挂到系统菜单，权限标识形如 `page:read:{页面key}`；支持多挂接（一个页面多个入口），挂接弹窗内管理已挂列表、可解除。也可选择一条已有菜单**覆盖**指向：菜单名称、目录、排序与角色授权保留，只把入口切到当前页面（适合替换旧入口，避免多出重复菜单）。
5. **另存为模板**：把整页或骨架沉淀为模板复用（见 [4.9](#4.9)）。

## 4.4 页面设计器总览

![页面设计器：列表 + 详情联动演示页](images/page-designer-demo.png)

设计器三段式布局：左侧组件面板与大纲，中间画布（桌面/平板/手机三种预览宽度），右侧属性面板。上图的演示页是页面侧最经典的联动结构：顶部步骤条展示流程阶段 → 中部**数据表格**展示客户档案 → 点击行后下方**数据详情**加载该条记录——这条联动链由 [4.8](#4.8) 的动作总线驱动。

组件面板按用途分组：

- **列表展示**：数据表格、卡片列表、树形数据、树形表格、日历、时间线、步骤条；
- **指标与图表**：KPI 指标卡、环比指标卡、统计图、数据图表、目标进度、排行榜、告警标记；
- **消息类**：待办清单、公告栏、公告轮播；
- **录入与详情**：数据录入（表单容器，绑定表单渲染录入界面）、数据详情（KV 展示单条记录）、数据容器（可被动作打开/关闭的容器，承载表单或详情）；
- **筛选与工具**：筛选器、计算公式（跨字段运算展示）；
- **表单组件复用**：数据引用、查找带回等表单侧组件也可拖入页面直接渲染，配置面板与表单设计器一致（组件对比见 [03 章 3.4](03-表单设计.md)）；
- **嵌入**：内嵌网页（iframe）。

## 4.5 数据表格与卡片列表的区别与配置

两个列表组件消费同样的页面数据源，差别在「长相」和「配置侧重」：

| | **数据表格** | **卡片列表** |
| --- | --- | --- |
| 长相 | 传统行列表格，信息密度高 | 卡片块状，一屏看摘要，视觉轻 |
| 适用 | 台账、管理后台、要多选批量处理的场景 | 门户首页、审批摘要、面向浏览者的展示 |
| 数据组织 | 一行一条，列对齐 | 每张卡片的字段按**角色**摆放：标题 / 副标题 / 标签 / 指标 / 普通字段 |

**数据表格常用配置项**：

- 搜索栏：字段级配置（文本框、下拉、日期、树选择、级联、查找带回等形态），一键查询/重置；
- 展示列：勾选字段、列宽、对齐、格式化、条件样式（按行数据改单元格样式）；
- 工具条：新增按钮开关、导出开关、自定义工具条按钮（挂动作链）；
- 操作列：行按钮（编辑/删除/自定义，可与默认增删改合并，超出自动折叠进「更多」）；
- 行为：服务器端排序、多选（选择变化事件）、行点击/双击、单元格点击触发动作；
- 树形表格：配置 rowKey 与 children 字段即切换为树形（树形下隐藏分页）；
- 弹窗表单模式：弹窗 / 页内内嵌两种新增编辑形态。

**卡片列表常用配置项**：

- 展示列（同上，勾字段 + 标签），每列可指定**卡片角色**（标题/副标题/标签/指标/字段）、栅格跨度（12 列栅格，12=整行）、排序权重、标签位置；
- 每列支持静态样式（颜色/字号/图标）与动态内容（表达式或模板拼装显示值）；
- 卡片整体样式：6 种内置主题（default/compact/loose/dark/borderless/techBlue）为基底，再叠加背景色、圆角、内边距、字段区布局（grid/list、每行卡片数）；
- 条件样式：按行数据命中规则切换卡片外观（如「已停用」整卡置灰）；
- 操作按钮与分页：与表格一致（按钮位置可放卡片顶部/底部/右侧）。

**怎么选**：用户要「逐行核对、批量操作」用表格；用户要「扫一眼挑一张点进去」用卡片列表。两者都支持点击行触发动作，联动能力见 [4.8](#4.8)。

## 4.6 页面数据源：为什么需要、如何配置

### 为什么不直接让组件选全局数据源？

页面里的组件（表格、卡片、容器、详情）统一通过「**页面数据源标识**」取数，而不是直接指到全局数据源。多这一层的好处：

1. **换源不动组件**：全局数据源要换实现（比如从 API 换成 SQL），只需在页面数据源绑定里改指向，所有组件无感；
2. **动作总线要靠它寻址**：总线动作的目标是「页面数据源标识」（见 [4.8](#4.8)），没绑定就配不了联动；
3. **状态防呆**：绑定下拉只列**已启用**的全局数据源，停用的源挂不进页面，避免页面带病发布；
4. **一处配置多处复用**：表格和卡片可以绑同一个页面数据源标识，筛选、刷新等总线动作一次生效。

### 如何配置

1. 页面设计器顶部工具栏点「**数据源配置**」按钮（按钮上显示当前绑定数，如「数据源配置 (4)」）；
2. 在「**数据源绑定**」Tab 添加一行：左边填**页面内标识**（自己起名，如 `ds_customer`，建议有业务含义），右边下拉选**全局数据源**（只列已启用的）；
3. 保存后在组件属性面板的「数据源」下拉里选这个页面内标识；
4. 同一弹窗的「**动作总线**」Tab 配置联动（见 [4.8](#4.8)）。

## 4.7 表单容器：在页面里录入和编辑业务数据

**应用场景**：列表页上点「新增/编辑」直接在页面内完成表单录入（含子表明细），不用跳去业务数据列表页——页面由此从「只读展示」升级为「完整业务操作」。典型页面结构见下图：上半部卡片列表展示订单，下半部数据容器承载订单录入表单（含订单明细子表、查找带回回填）。

![页面设计器：卡片列表 + 数据容器（表单录入）](images/page-designer-cardlist.png)

涉及两个组件：

- **数据录入**：绑定表单/数据源后渲染录入界面，是「装表单的容器」；
- **数据容器**：可被动作打开/关闭的容器外壳，承载表单或数据详情，配合「打开容器/关闭容器」动作做弹层交互。

**关键配置项**：

| 配置 | 说明 |
| --- | --- |
| 数据源 | 选页面数据源标识，容器从这取/存数据 |
| 容器地址 | 容器的字段名（`rule.field`），见下方「容器寻址」 |
| 记录定位 | 默认 `current-record`（当前记录）——总线把行 id 传进来后加载该条 |
| 展示形态 | 弹窗 / 新标签页 / 页内内嵌；对应可配弹窗宽高、标签页标题、内嵌高度 |
| 按钮开关 | 新增、取消、确认、删除、复制逐个开关；也可配自定义按钮 |

**容器寻址规则**（多容器页面必读）：

- 容器地址 = 表单容器的字段名（`rule.field`），数据源只负责取数；
- 同一数据源挂了多个容器时，靠容器地址区分目标；
- 动作配置里的 target 填地址优先匹配，留空则回退到该数据源关联的首个容器。

**标准用法**：拖入容器 → 绑定页面数据源 → 在动作总线里配「表格行点击 → 打开容器 + 加载记录 → 用户改完点确认 → 保存容器 → 刷新列表」这条链（见 [4.8](#4.8)）。配置动作时面板会自动列出画布上的容器作为候选，从下拉选即可。

## 4.8 两套交互：事件动作链 与 动作总线

平台有两套并存的交互配置体系，按配置层级区分，不要混用：**体系 A（组件级事件动作链）** 配在组件自己的弹窗里，管「这个组件发生什么时做什么」；**体系 B（页面级动作总线）** 配在页面级弹窗里，管「跨组件怎么联动」。

### 4.8.1 配置入口总览

| # | 入口 | 位置 | 适合 |
| --- | --- | --- | --- |
| 1 | **页面级动作总线** | 设计器工具栏「数据源配置」弹窗 → 动作总线 Tab | 跨组件联动（点行刷详情、加载/保存容器） |
| 2 | **组件操作按钮**（ActionsConfig） | 表格/卡片的「配置数据源」弹窗 → 操作 Tab | 「这个按钮点了做什么」 |
| 3 | **组件事件**（EventsConfig） | 同一弹窗 → 事件 Tab | 行点击、搜索、加载成功、弹窗开关等组件自身事件 |
| 4 | **列高级配置**（ColumnAdvancedConfig） | 展示列每行的「高级配置」 | 单元格点击动作、列内容表达式/模板、字体样式 |
| 5 | **表单事件** | 表单设计器 → 表单配置 →「设置事件」 | 表单提交成功/字段变化等表单级钩子 |

入口 2/3 在同一个「卡片列表数据源配置」弹窗里（表格组件对应「搜索表格数据源配置」，结构相同），入口 5 的界面见下图——表单级钩子按生命周期列出：onSubmit（提交时触发）、onReset、onCreated、onMounted、onChange（字段值变化）、beforeSubmit（验证通过后、提交前，可拦截）、beforeFetch（远程数据请求前）等，点选后在右侧写处理逻辑。

![表单事件：表单级生命周期钩子](images/form-events.png)

### 4.8.2 体系 B：页面级动作总线

工具栏点「数据源配置」→ 切到「动作总线」Tab。总线是**跨组件联动的调度中心**：一个组件发生事件，总线按「触发器 + 来源过滤」命中一条动作，再按步骤序列驱动其他组件。没有总线时这类「点这里、动那里」只能靠脚本；有了总线，全是配置，且组件之间不互相引用、都只跟总线打交道。

![页面级动作总线：触发器 + 动作步骤](images/bus-panel.png)

上图要点：

- 点「**+ 添加动作**」新增一条总线动作。第一行：左边选**触发器**（树节点点击、表格行点击、行编辑/查看/新增、字段变化、记录变化），右边「**来源数据源**」做来源过滤——只响应来自该数据源组件的事件，页面里同类组件多时用它区分（留空 = 不限来源）；
- 第二行起是**动作步骤**（下拉切换操作类型），每条动作内可加多个步骤（「+ 步骤」），按顺序执行——比如「打开容器 → 加载记录」两步；
- 容器类操作（打开/关闭容器、加载/保存记录）第二个下拉选**容器**（候选自动列出画布上的表单容器）；数据类操作（设置过滤、刷新数据）选**页面数据源标识**；
- 底部提示条写明值模板写法：`{node.id}`（树节点标识）、`{row.id}`（表格行标识），输入 `{` 时编辑器会弹出**当前触发器可用变量**的候选列表（见 [4.8.6](#4.8.6)）。

可用操作：设置过滤、刷新数据、重载记录、保存记录、打开容器、加载记录、保存容器、关闭容器（「设置字段值」运行时已支持但暂未开放配置入口，**【规划中】**）。

target 的填法：容器类操作填**容器地址**（表单容器的字段名 `rule.field`，候选下拉直接选）；数据类操作填**页面数据源标识**。留空则回退到该数据源关联的首个容器。

### 4.8.3 体系 A 之一：组件操作按钮（操作 Tab）

表格/卡片点「配置数据源」→「操作」Tab，管的是按钮级行为：

![操作 Tab：内置按钮 + 自定义按钮](images/actions-config.png)

- **内置按钮**：编辑、删除默认提供，可逐个开关/改文案；
- **自定义按钮**：点「+ 添加自定义按钮」，填按钮文案，再为它配动作链（动作类型 + 参数）；
- **表单方式**：该组件的新增/编辑用哪种形态——弹窗（可配宽高）或页内内嵌；配合 [4.7](#4.7) 的表单容器使用；
- **权限点**：每个按钮可绑权限标识，运行时无权限的用户看不到按钮。

动作链的动作项 = 动作类型 + 参数键值对，常用动作：设置筛选、刷新数据、打开详情、打开链接、消息提示、编辑、删除、导出、打开容器、关闭容器、加载记录、保存容器、设置分页、设置排序、清空选择、脚本。

### 4.8.4 体系 A 之二：组件事件（事件 Tab）

同一弹窗的「事件」Tab 配组件自身的事件动作链（声明式）：

![事件 Tab：触发器 + 动作链](images/events-config.png)

- 点「**+ 添加事件**」生成一个事件块：选**触发器**（行点击、单元格点击、搜索、刷新、新增成功、行选择变化、弹窗打开/关闭、加载成功、保存成功、删除成功等；卡片模式下不出现表格专属触发器），可填**目标**组件 id 做联动；
- 每个事件下加动作（「+ 动作」），动作里再「+ 参数」填键值对；
- 底部变量提示：参数值里可用 `$row.字段`（当前行）、`$param.参数`（页面参数）——这是体系 A 的模板写法，**与总线 B 的 `{row.id}` 花括号写法不同**，两边别写混。

### 4.8.5 体系 A 之三：列高级配置

展示列每行的「高级配置」打开字段级弹窗（表格列标题为「高级配置」，卡片列标题为「字段高级配置」）：

![列高级配置：内容模式 + 点击动作 + 卡片角色](images/column-advanced.png)

- **基础设置** Tab：**内容模式**（原值 / 表达式 / 模板——表达式与模板输入框都是带补全的代码编辑器，见 [4.8.6](#4.8.6)）、**样式脚本**（按当前字段数据动态生成 CSS）、**对齐 / 基础 class**、**点击动作**（点这个单元格触发动作链，如点单号打开详情）、表格列还有**汇总**（合计/平均等）；
- **卡片配置** Tab（仅卡片模式）：**角色**（普通字段/标题/副标题/标签/指标——决定该字段在卡片上的位置和样式权重）、对齐、字体、字号、字重、颜色、显示标签与标签位置。

### 4.8.6 表达式与脚本里怎么选变量

所有表达式/脚本输入框共用同一个 CodeMirror 6 编辑器组件，补全行为按场景分三种：

1. **`{{变量}}` 模板**（动作链参数、列模板、逻辑流节点参数等）：输入 `{{` 立即弹出**当前上下文可用变量**的候选列表（表单字段、页面参数、系统变量等），↑↓ 移动、Enter 选中后自动补全为 `{{变量名}}` 占位符并高亮；在 `{{` 内继续输入可按前缀过滤；
2. **裸表达式**（条件表达式、UEL/Groovy 类）：不用占位符，标识符**即输即补**——打出变量前几个字母就出候选；
3. **SQL 编辑器**（SQL 数据源）：SQL 关键字高亮 + 关键字补全，字符串里同样支持 `{{变量}}` 模板补全，还带表列/函数的结构化提示。

配置总线动作值时输入 `{`（单个花括号）即列出当前触发器可用的模板（如 `{row.id}`）——因为模板根名/字段名拼错**不会报错、只静默取空**，强烈建议从候选列表选而不是手打。

各处候选变量从哪来：

| 场景 | 候选来源 |
| --- | --- |
| 动作链参数 / 列模板 | 当前行字段（`$row.`）、页面参数（`$param.`） |
| 总线步骤值 | 当前触发器的 eventData 根（行类触发器有 `row`/`node`，字段变化只有 `field`/`value`/`record`） |
| 逻辑流节点参数 | 流程变量 + 触发上下文（截图见 [06 章 6.3](06-逻辑编排.md)） |
| 流程连线条件表达式 | 流程变量（下拉选择） |
| SQL 数据源 | 所选表的列 |

### 4.8.7 选型建议与脚本动作

- 单个表格/卡片自己按钮的行为 → 用动作链（体系 A），就近配置；
- 跨组件联动（点左树刷右表、点行在容器里加载记录再保存）→ 用总线（体系 B），集中管理。

动作链支持「脚本」动作：JS 代码沙箱执行，上下文可取 `row / ds / actions / params`。脚本默认关闭，需部署时设置环境变量 `VITE_PAGE_SCRIPT_ENABLED=true` 才会执行——没看到脚本效果时先确认这项。

## 4.9 页面模板

页面列表的「模板」Tab 提供两个形态：

- **完整模板**：整页原样复制，实例化后独立演化；
- **骨架模板**：只留组件结构与锚点，数据源/表单槽位在实例化时让用户逐个绑定。另存为骨架时需给每个槽位起「锚点名称」（实例化时展示给使用者的绑定向导文案，建议起「主列表」「详情容器」这类业务含义名）。

团队里重复搭同类页面（如各类台账）时，先由骨干搭一页存为骨架模板，其他人从模板实例化只填数据源，一致性最好。

## 4.10 存量视图（VIEW 轨）

早期以「视图设计器」产出的列表查询页面（勾选筛选字段、展示列、操作按钮即成页，绑定 FORM/WORKFLOW 数据源），经通用渲染页 `/page/:pageKey` 展示。现状：

- 存量视图继续可用、可挂菜单、受同样的访问控制；
- 新建页面不再提供视图类型选项，统一走自定义页面；
- 新需求建议直接用自定义页面的数据表格组件，能力是视图的超集。

## 4.11 常见问题

**Q：页面发布成功，但用户点开是 404/403？**
404 多半是页面没挂任何菜单（后端按「无关联菜单 → 404」处理）；403 是用户所属角色未被授予对应菜单权限。见 [08 权限与菜单](08-权限与菜单.md)。

**Q：组件属性里找不到想要的数据源？**
组件选的是「页面数据源标识」，不是全局数据源名。先在工具栏「数据源配置」里把全局数据源绑成页面内标识（见 [4.6](#4.6)），停用的全局数据源不会出现在绑定下拉里。

**Q：动作选了「加载记录」但没反应？**
检查 target：容器地址填的是表单容器的字段名，不是显示标题；留空则找该数据源关联的首个容器。确认画布上确实存在对应容器。

**Q：模板变量 `{row.id}` 取值为空？**
总线步骤的值是从触发事件的 eventData 里按点路径取的，不同触发器可用的根不同（如行类触发器有 `row`/`node`，字段变化只有 `field`/`value`/`record`），根名写错会静默取空。配置面板的变量候选下拉按触发器给出，建议从下拉选而不是手打。

**Q：卡片列表想显示多行字段组合？**
给展示列配「模板/表达式」动态内容，或用卡片整体条件样式；要求比「展示列勾选」灵活。
