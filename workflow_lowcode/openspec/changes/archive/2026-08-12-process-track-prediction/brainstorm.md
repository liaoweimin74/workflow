## Design Summary

流程跟踪（ProcessInstanceTrackPage）新增后续节点预测功能。当前页面只展示流程图高亮，用户无法看到已执行任务详情和后续将要执行的节点。本设计在流程图下方新增任务执行列表，同时在后端实现 BPMN 拓扑路径遍历，预测从当前活跃节点出发的后续执行路径。

## Alternatives Considered

### 方案 A：仅流程图颜色区分
- **做法**：在流程图上用不同颜色标记已执行、当前活跃、未执行节点
- **优点**：不新增 UI 元素，改动最小
- **缺点**：无法展示驳回/转办等审批动作细节，无法展示办理人/时间/意见等信息
- **为何未采用**：用户明确表示驳回和转办无法在流程图上清晰展现

### 方案 B：流程图下方加任务列表（已执行节点）
- **做法**：在流程图下方新增一个表格，展示已执行完成的节点信息（节点名称、办理人、时间、动作、意见）
- **优点**：可以展示完整的审批动作信息
- **缺点**：无法展示后续将要执行的节点，用户看不到流程"接下来会走到哪"

### 方案 C：已执行节点 + 后续预测节点列表（Agreed）
- **做法**：任务列表同时展示已执行节点和预测的后续节点。后端实现 BPMN 拓扑遍历引擎，从当前活跃节点出发沿出线遍历，预测后续路径
- **优点**：完整展示流程全貌，从已执行到预测执行，用户能清晰看到"下一步会走到哪"
- **缺点**：需要实现 BPMN 拓扑解析，排他网关的分支预测受限于条件评估

## Agreed Approach

采用方案 C，核心规则：

1. **历史节点**：已执行完成的节点之间用**实线**连接
2. **当前活跃节点**：与上一个已完成节点实线连接
3. **预测节点**：从当前活跃节点出发，沿着出线遍历：
   - 无条件连线 → 直接走，继续遍历下一个节点
   - 有条件连线 → **停止遍历**，不画线，标记当前节点为"有分支"
   - 走到结束事件（endEvent）→ 用虚线连接
4. **结束节点**：无条件节点与结束节点之间虚线连接；有条件节点不连

## Key Decisions

1. **连线规则**：实线（已执行）和虚线（预测路径），区分已完成和未来
2. **分支处理**：遇到有条件连线即停止，不预测分支走向，避免基于条件表达式评估的不可靠性
3. **并行网关**：与分支一样处理，从当前活跃节点沿出线遍历
4. **展示形式**：表格形式，位于流程图下方，替代原有的"审批记录"卡片
5. **审批记录**：保留时间线视图，改为折叠/收起，默认展示任务执行列表

## Open Questions

1. 并行网关场景下，多个活跃节点同时存在时，表格如何排序？按时间还是按拓扑？
2. 默认流（default flow）是否视为无条件连线？
