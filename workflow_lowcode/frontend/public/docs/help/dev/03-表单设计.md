# 03 表单设计

表单是平台的数据建模入口：字段定义 + 校验规则 + 界面布局，发布后即成为可录入、可查询的业务数据。

## 3.1 表单的两种类型

在 **开发管理 → 表单列表** 新建表单时需要选类型：

| 类型 | 数据去向 | 典型用途 |
| --- | --- | --- |
| **业务表单** | 发布时生成独立业务数据表，数据可持续增删改查 | 台账、填报、主数据 |
| **工作流表单** | 数据随流程实例存储（流程发起/审批过程填报），不生成独立业务表 | 请假单、报销单 |

状态机：`草稿（可编辑、可发布）→ 已发布`，已发布表单还支持启用/停用。

**跨类型复制**：表单列表的「复制」支持把表单复制成另一种类型（工作流 ↔ 业务），两种方向有不同的校验提示：

- 工作流 → 业务：发布时校验组件白名单与列映射，含审批类组件需先调整，未配置列映射无法发布；
- 业务 → 工作流：副本仅作流程发起用，不再生成业务数据表，列映射不会随复制保留。

## 3.2 设计器布局与组件面板

表单列表 → 「设计」进入表单设计器。左侧组件面板分六组：**基础组件、图表组件、系统组件、子表单组件、辅助组件、布局组件**。常用组件如下：

![表单设计器：销售订单（查找带回回填、关联记录卡片、订单明细子表）](images/form-designer.png)

上图为一个典型的「销售订单」业务表单：顶部通过**查找带回**选择客户后自动回填联系人、联系电话，左侧卡片展示客户的**关联记录**，下方用**表格表单**录入订单明细——这三种平台特色能力分别在 3.3、3.4 展开。

**基础录入类**：单行文本、多行文本、数值、密码、单选组、多选组、下拉选择、开关、评分、滑块、日期、日期范围、时间、时间范围、文件上传、富文本、图片、颜色、级联选择、树选择、地区选择、位置选择、穿梭框。

**平台特色组件**（业务开发重点）：

| 组件 | 作用 | 要点 |
| --- | --- | --- |
| 自动编号 | 提交时生成「前缀+日期+流水」的唯一编号 | 适合单号、工单号；字段为字符串列 |
| 字典选择 | 下拉选项绑定数据字典 | 需先在「系统管理 → 字典管理」建好字典（见管理手册） |
| 计算公式 | 按同表单其他字段实时算值 | 表达式用 `${字段名}` 引用，支持 `+ - * / %` 与 `MIN/MAX/SUM/AVG/ABS/ROUND/FLOOR/CEIL`；有可视化配置弹窗；可设小数位、前后缀 |
| 用户 / 部门选择 | 选人、选组织 | 在「系统组件」组；支持多选 |
| 手写签名 | 电子签名板 | 审批签字场景 |
| 数据引用 / 查找带回 | 跨表单选记录（详见 [3.4](#3.4)） | 表单设计器与页面设计器都可拖入 |
| 子表单 / 表格表单 / 分组 | 主子表与布局（详见 [3.3](#3.3)） | 在「子表单组件」组 |
| 分步表单（stepsForm） | 长表单分步填写 | 引导式录入 |
| 数据表格 / 卡片列表 | 在表单里嵌入展示其他数据源 | 复用页面侧的展示组件，数据取自表单级数据源绑定 |

**布局类**：栅格行列（row/col）、选项卡 tabs、折叠面板、卡片、分组、间距、分割线、标题、静态文本、告警提示、内嵌 HTML。

## 3.3 主子表：子表单、表格表单与分组的区别

「一对多」是业务表单最常见的主子结构（订单 ↔ 订单明细）。子表单组件组里有三个名字相近的组件，定位完全不同：

| | **表格表单** | **子表单** | **分组** |
| --- | --- | --- | --- |
| 数据形态 | 数组（一对多，真子表） | 数组（一对多，真子表） | 对象（不产生重复数据） |
| 外观 | Excel 式表格，一行一条 | 卡片式重复块，字段自由排版 | 纯视觉分组/折叠容器 |
| 条数控制 | 加/删行按钮 | 可设最少/最多条数 | — |
| 列级配置 | 子列支持标题、对齐、必填、隐藏、列宽、颜色、格式化、固定列 | 子字段按普通字段属性配置 | — |
| 事件 | 变化 / 加行 / 删行 | — | — |
| 适用场景 | 明细行多、字段规整（订单明细、报销明细） | 条数少、希望每条有独立排版（联系方式多组、分段资料） | 只是视觉上把字段归组，与主子表无关 |

**怎么选**：

- 要的是「明细行」→ 在**表格表单**和**子表单**里选：行数可能很多、列对齐好看优先 → 表格表单；每条记录字段排版复杂（每条占一大块）→ 子表单；
- 只是想把几个字段框在一起 → 用**分组**，它不会生成子表数据。

**存储说明**：表格表单与子表单发布后会创建独立物理子表 `wf_biz_<formKey>_<子表字段名>`（子行通过 biz_id 关联主表行），所以明细数据可直接被数据源、逻辑流按表查询；分组不建表。子表结构变更规则与主表一致：只增不减、禁删列、禁类型跨类变更。

三个组件都只在表单设计器中拖入；已发布表单的一对多数据在页面侧由数据表格/数据录入组件消费（见 [04 章 4.4 表单容器](04-页面与数据源.md#4.4)）。

## 3.4 数据引用与查找带回

两个组件解决同一个问题——**在 A 表单里引用 B 数据源的记录**——区别在于「要不要连带带出对方的其他字段」：

| 配置项 | 数据引用 | 查找带回 | 说明 |
| --- | --- | --- | --- |
| 数据源 | ✅ | ✅ | 选已启用的数据源 |
| 显示字段 | ✅ | ✅ | 弹窗/输入框里展示哪个字段（必填） |
| 列表显示列 | ✅ | ✅ | 选择弹窗里展示的列 |
| 搜索列 | ✅ | ✅ | 弹窗顶部按哪些列模糊搜索 |
| 最多可选数 | ✅ | ✅ | 1 = 单选（点行即选中）；大于 1 = 多选并限制勾选数 |
| 级联变化时清空 | ✅ | ✅ | 上游关联字段变化时清空已选值，防脏引用 |
| 允许新增目标记录 | ✅ | ✅ | 弹窗里直接新建一条对方记录 |
| 详情弹窗表单只读 | ✅ | ✅ | 点开记录详情时只读展示 |
| **id 存储字段** | — | ✅ | 选中记录的 id 存到本表单哪个字段 |
| **返回字段映射** | — | ✅ | 源字段 → 本表单字段的映射，选中后**自动回填**多个字段 |

**怎么选**：

- 只需要「指向」对方记录（如订单上选客户，展示时再解析）→ **数据引用**；
- 希望选中后把对方的联系人、电话等直接填进本表单字段（见 [3.2](#3.2) 截图：选客户后自动回填联系人/联系电话）→ **查找带回**。

两个组件在**页面设计器**里同样可拖入使用，配置面板一致（页面侧示例见 [04 章](04-页面与数据源.md)）。

## 3.5 字段属性与校验

选中字段后，右侧属性面板常见项：标题、字段名（key，发布后慎改）、占位提示、默认值、禁用/只读、必填。校验支持必填、长度、数值范围、正则等（按组件类型出现对应项）。

**字段权限**：表单可配置字段级可见性，取值为 `可编辑 / 只读（VIEW）/ 隐藏` 三态，用于「创建时填写、审批时仅查看」这类场景；在流程节点上按节点生效（详见 [05 流程编排](05-流程编排.md)）。

## 3.6 发布与数据

- 发布前建议用设计器自带的预览确认布局；
- 业务表单发布后，表单列表会出现「数据」类入口（业务数据列表页），可以直接增删改查这张表的数据——不建页面也能先用；
- 页面/数据源消费该表单时，通过 FORM 数据源包装（见 [04 页面与数据源](04-页面与数据源.md)）；
- 已被引用的表单在列表上有引用计数提示，删改前先确认引用方。

## 3.7 常见问题

**Q：子表单和表格表单发布后数据存在哪？**
存在**独立物理子表** `wf_biz_<formKey>_<子表字段名>`，每行带固定列（id、biz_id 关联主表行、tenant_id、sort_no 行序、version、审计时间戳），子列就是表单里拖入的子字段。分组（subForm）不产生数据、不建表。「分组」只是布局容器；嵌套子表（子表里再放子表）不支持，发布时会被标记为不可映射。

**Q：改已发布表单的字段，数据会怎样？**
字段名（key）是数据表列的锚点，改名等于换列，历史数据不会自动迁移。要调整结构：新增字段是安全的；删除或改名会让旧数据在报表/页面中失联，请先导出备份。

**Q：下拉选项总变，要反复改表单吗？**
不用。改用「字典选择」组件绑定字典，管理员在「系统管理 → 字典管理」维护选项即可（见[管理手册 03 章](../admin/03-字典与菜单.md)）。

**Q：金额小计想自动算？**
用「计算公式」组件：`${单价} * ${数量}`，精度设为 2。

**Q：编号规则里的日期能自定义吗？**
自动编号支持前缀 + 日期段 + 流水的组合，具体粒度（日/月重置等）以配置弹窗的选项为准；规则不满足时可先用逻辑流生成再回写。
