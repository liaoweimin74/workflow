# 08 权限与菜单

菜单是「入口 + 权限载体」，角色是「权限的打包」。上线前每一项功能都要走完：**挂菜单 → 授角色 → 到用户**。

## 8.1 菜单的三种类型

入口：**开发管理 → 菜单管理**（树表结构，支持拖拽调整层级与顺序）。

![菜单管理树表](images/menu-tree.png)

| 类型 | 作用 | 例子 |
| --- | --- | --- |
| 目录 | 一级分组，不指向页面 | 开发管理、系统管理 |
| 菜单 | 可点击的页面入口，有路由 path 与权限标识 | 设备报修管理（`/page/repair`） |
| 按钮 | 挂在菜单下的细粒度权限项，控制页面内操作 | 用户新增（`system:user:create`） |

树表里每行对应一条菜单，「类型」列区分目录/菜单/按钮；菜单行的「路由路径、组件路径、权限标识」三列是排障时最常核对的字段——入口打不开先看这三列与实际是否一致。

点击「编辑」弹出的表单字段如下：

![菜单编辑弹窗](images/menu-edit.png)

| 字段 | 说明 |
| --- | --- |
| 上级菜单 | 决定菜单挂在哪个目录下（根级/某目录），支持搜索 |
| 菜单类型 | 目录 / 菜单 / 按钮（建按钮项时挂在某菜单下） |
| 菜单名称 | 侧边栏显示名 |
| 关联页面 | 可选，选择已发布的自定义页面——关联后访问控制走 [8.3](#8.3) 的双重校验 |
| 路由路径 | 点击菜单跳转的地址，如 `/page/repair`、`/system/menu` |
| 图标 | 侧边栏图标 |
| 可见 | 「隐藏」时不在侧边栏显示但仍可作为权限载体（如仅做权限控制的父节点） |
| 组件路径 | 普通路由页填 views 下组件相对路径（如 `system/menu/index`）；远程物料页固定填 `material:<物料key>` |
| 权限标识 | 后端校验用的权限串，页面类为 `page:read:{页面key}`，按钮类为 `模块:资源:动作` |
| 排序 | 同级显示顺序 |

权限标识命名约定（自建时请沿用）：`模块:资源:动作`，如 `system:dict:update`、`form:publish`、`process:definition:deploy`；页面类固定为 `page:read:{页面key}`。

## 8.2 页面挂接菜单的两种方式

1. **一键挂接（推荐）**：页面列表 / 物料对已发布页点「挂接菜单」，平台自动创建菜单（path=`/page/{页面key}`，permission=`page:read:{页面key}`）。支持多挂接：同一页面挂多个入口（不同目录、不同名称），在挂接弹窗管理已挂列表、可逐条解除（解除为软删）。
2. **手动创建**：菜单管理里手工新建（弹窗字段见 [8.1](#8.1) 的字段表），适合普通路由页面或非标准路径；权限标识务必填 `page:read:{页面key}`，否则后端校验对不上。

## 8.3 自定义页面的访问控制（双重）

平台对页面类功能做前后端双重校验，规则如下：

- **前端**：用户菜单树里没有该菜单 → 入口不可见；
- **后端**（渲染与数据接口都校验）：
  - 页面**没有任何关联菜单** → 404（视为未投放）；
  - 用户拥有**任一**关联菜单的权限 → 放行；
  - 有菜单但全部无权限 → 403；
- 设计器预览（preview 参数）豁免校验，仅开发者自己可见。

由此推出两个常见现象：

- 「发布成功但访问 404」＝ 忘了挂菜单；
- 「403」＝ 菜单挂了，但用户所属角色没勾上这个菜单（或勾了未保存/用户未重新登录）。

## 8.4 角色授权

**系统管理 → 角色管理** → 选角色 → 菜单权限树：

![角色菜单授权](images/role-menu.png)

- 树勾选以菜单为单位，展开可细勾按钮项；
- 只勾子菜单时，平台会自动补齐其祖先目录（否则菜单树显示不出来），不必手动勾目录；
- 内置超级管理员角色默认拥有全部菜单，无需维护。

用户获得权限：用户关联角色 → 用户重新登录生效。给多人批量放权时优先建角色打包，避免逐用户配置。

## 8.5 数据权限（行级数据范围）

8.1～8.4 管的是「能不能进这个功能」，本节管「进来之后能看见哪些行」。两层互不替代：菜单权限放开了页面，数据权限仍可能让列表一片空白。

### 三条语义

| 语义 | 含义 | 配错时的表现 |
| --- | --- | --- |
| **关联即受控** | 数据源只要挂上了权限对象，就进入数据权限管辖；没挂的源不受控，全租户可见 | 想「暂时不限制」却留着一个对象还关联着源 → 该源所有人都看不见 |
| **授权即赋予** | 授权是给某个角色「能看见对象圈定的行」，不是给角色套限制；角色没被授权任何对象，在受控源上就是 0 行 | 建了对象、关联了源，但没去角色管理勾选 → 忘记自己配过受控，列表空 |
| **看即能操作** | 数据权限就是查看权限：看不见的行同样改不了、删不了，不再分读/写两套勾选 | 想「只给看不给改」做不到，这一版没有该能力 |

多条规则的关系固定为：**对象内条件 AND，对象间 OR**。同一角色命中多个对象时取并集；空条件对象 = 该源全部行，用来给需要看全量的角色放权。

### 两个配置入口

配置被拆成两端，各自是唯一写入口，不存在第三处能改：

1. **开发管理 → 数据权限 → 权限对象**（定义规则）：新建对象，填名称、写条件（组内 AND）、关联数据源。这里改条件或换源都不会动已有授权。
2. **系统管理 → 角色管理 → 数据权限**（授予角色）：列出全部权限对象，按对象勾选要授给该角色的项，保存只影响本角色。

用户生效路径与菜单权限相同：用户关联角色 → 重新登录。

### 条件写法

条件按列名施加到每个关联数据源，列名候选由后端按「所选源都能筛出的列交集」给出。取值支持字面量与变量：

| 变量 | 取值 | 用法 |
| --- | --- | --- |
| `{userId}` | 当前用户 id | 单值，可拼进字面量 |
| `{username}` | 当前用户名 | 单值，可拼进字面量 |
| `{orgId}` | 当前用户所属部门 id | 单值，可拼进字面量（如 LIKE 配 `{orgId}/%`） |
| `{orgIdSubtree}` | 当前部门及全部下级 id 列表 | **集合变量**：必须独占整个取值，且只能配 `IN` |

典型配法：「只看自己录入的」= `created_by eq {userId}`；「看本部门及下级」= `dept_id in {orgIdSubtree}`；「看全部」= 建一个不写任何条件的对象。

### 覆盖度盘点与豁免

**开发管理 → 数据权限 → 覆盖度盘点** 按数据源逐个回答「受不受控、控住了有没有人授到」，四种状态：

- **已受控**：挂了对象且至少一个对象授权给了角色；
- **未授权**：挂了对象但没有任何角色被授权，非管理员在该源上一行都看不见——这是最容易踩的空档；
- **缺口**：没挂对象，该源对全体登录用户可见；
- **已豁免**：接受某个缺口并把理由留痕（理由必填，撤销是软撤销，记录不删）。

### 生效范围（同一张表的两条读通道）

一张业务底表有两条以登录用户身份直读的通道，范围条件在两条通道上口径一致——同一条数据在两边看到的行数相同：

| 入口 | 接口 | 判定依据 |
| --- | --- | --- |
| 数据源管理 → 数据管理 | `/api/v1/data-sources/{id}/data` | 数据源 id |
| 表单管理 → 管理数据 | `/api/v1/biz-data/{formKey}` | 用 formKey 反查出它绑定的数据源，再走同一份判定 |

页面运行态、Excel 导入导出走的仍是第一条（数据源 id），因此自动一致。

三类请求**不参与**范围判定，这是明确的产品决定：

- **新增**：新行还没有归属可比（见下方「边界与坑」）；
- **引用显示文本解析**（`/biz-data/{formKey}/resolve`）：按 id 还原标签文本，收紧会让已保存的引用整体空掉；
- **独立子表行**的增删改查：子表没有自己的数据源，不按主表行的范围连带判定。

### 边界与坑

- 只有 **FORM / SQL** 数据源能被范围约束。SYSTEM、API、WORKFLOW 三类源根本不消费筛选条件，挂上对象后端会直接报 400，不会静默放行造成「看着已收紧实则没有」的假保障。
- 新增记录不做行校验（新行还没有归属可比），能不能新增归功能权限（菜单/按钮）管。
- 条件的列必须在**所有**关联源上都可筛，否则保存被拒并点名是哪个源——否则查询期会让整个列表报错。
- 服务端保留一个内部筛选通道传递范围条件，客户端传来的同名字段一律丢弃，前端传的 OR/AND 筛选与范围条件是 AND 叠加，互不覆盖。
- 管理员角色（`admin` / `ROLE_ADMIN`）豁免，不受任何范围约束，方便兜底排查。
- 用业务表单钩子**接管了查询**的表单，钩子必须声明自己认数据范围（`honorsRowScope()`，见 [09 自定义开发 9.4.1](09-自定义开发.md#9.4.1)）；没声明的表单在关联权限对象时直接 400，不给你「以为收紧了」的机会。
- 删掉一个对象会连带清掉它的授权与关联；如果这是该源唯一的对象，该源随即回到「不受控、全员可见」。

数据权限不改变多租户隔离：租户过滤始终自动生效，行范围是在本租户之内的再收紧。需要更复杂的行级逻辑（跨表、按流程状态）时，仍可用业务表单钩子接管查询实现（见 [09 自定义开发 9.4.1](09-自定义开发.md#9.4.1) 的 `EmpProfileHandler` 示例）。

## 8.6 排障清单

用户说「看不到 / 打不开某功能」时按序检查：

1. 功能本身状态：表单/页面/逻辑流是否已发布并启用；
2. 入口：页面是否挂接了菜单（挂接弹窗里查已挂列表）；
3. 授权：角色权限树是否勾了该菜单（注意按钮项）；
4. 数据：列表能进但空白 → 查「开发管理 → 数据权限 → 覆盖度盘点」，该源是否处于**未授权**（挂了对象没人授到）或角色缺对应对象授权；
5. 用户：账号是否关联了该角色、是否重新登录、账号与菜单是否处于启用状态；
6. 环境：该用户的租户/组织是否正确（跨租户默认互相不可见）。
