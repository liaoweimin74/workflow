## Design Summary

开发一个三栏穿梭式审批人选择组件 `ApproverPicker`，替换 `UserTaskProperty.vue` 中纯文本「审批用户」输入框。

**布局**：弹窗 900px，三栏 `200px : 1fr : 240px`。
- 顶部：全局姓名/电话搜索框（回车+按钮触发，全局搜索忽略筛选）+ 已选人数提示。
- 左栏：Tab 切换「组织树」「角色列表」。组织树用 `el-tree` + checkbox（数据 `getOrgTree()`），角色列表用 checkbox 列表（数据 `getRoleList({size:999})`）。两者各带搜索框。勾选状态独立保留，合并生效（OR）。
- 中栏：待选用户 `el-table` + checkbox 列（昵称、部门）。按左侧勾选的组织/角色合并查询，去重，分页 size=20。已选行同步勾选。
- 右栏：已选用户列表（昵称+部门+×），底部「清空」。× 删除时同步取消中栏勾选。
- 底部：取消 / 确定。

**数据契约**：
- `modelValue: number[]`（用户 ID 数组），`change` 事件带 `{id, nickname, username, orgName}[]`。
- 打开弹窗时根据 modelValue 批量拉用户详情初始化已选集。

**后端改造**：
- `UserQueryRequest` 加 `orgIds: number[]`、`roleIds: number[]` 数组字段。
- `UserServiceImpl.list()` 的 Specification 用 `cb.or(...)` 合并多组织/多角色 OR 查询，支持分页。
- 新增 `GET /users/batch?ids=1,2,3` 批量查用户接口。

**旧数据**：`designerStore.NodeConfigData.approval` 直接把 `value: string` 改为 `userIds: number[]`，不兼容旧字符串数据。

## Alternatives Considered

### 方案 A：三栏穿梭式（左 Tab + 中待选 + 右已选）
- **做法**：左栏 Tab 切换组织树/角色列表，多选勾选后合并查询用户到中栏，中栏勾选加入右栏已选。
- **优点**：组织层级直观（树）、可同时多选组织和角色合并查、已选状态可视化、符合企业微信/钉钉选人习惯。
- **缺点**：组件复杂度高（三栏 + Tab + 同步逻辑）、弹窗较宽（900px）。
- **为何未采纳**：✅ 已采纳为本方案。

### 方案 B：单表格弹窗（复用 LookupPicker + 顶部筛选条）
- **做法**：弹窗内顶部放组织下拉+角色下拉+关键字输入，下方单 `el-table` 多选用户。
- **优点**：复用现有 `LookupPicker`，开发量最小、弹窗窄（700px）。
- **缺点**：组织是树结构，下拉无法体现层级；不能同时选多个组织/角色合并查；已选无独立可视化区域。
- **为何未采纳**：用户明确要求左侧组织树 + 角色列表 Tab + 右侧已选区，单表格无法满足。

### 方案 C：左树/左列表双 Tab（切换式，非合并）
- **做法**：左侧 Tab 切换「按组织」「按角色」两个独立视图，切换后只展示当前维度，不能同时叠加组织和角色筛选。
- **优点**：交互简单、查询逻辑简单（单维度）。
- **缺点**：不能同时按组织+角色筛选，用户需求是两者可合并多选。
- **为何未采纳**：用户明确要求"勾选多个组织/角色，合并查用户"，切换式无法合并两个维度。

## Agreed Approach

采纳**方案 A：三栏穿梭式**。

胜出理由：
1. 用户在 brainstorming 中明确描述了三栏布局（左 Tab、中待选、右已选）。
2. 组织树多选 + 角色列表多选合并 OR 查询，是方案 B/C 无法实现的核心需求。
3. 已选区独立可视化 + × 删除 + 待选区同步勾选，是选人场景的标准交互，体验最佳。
4. 虽然组件复杂度高，但作为可复用组件一次投入长期受益。

## Key Decisions

1. **组件形态**：独立 `ApproverPicker.vue` 组件，不内联在 UserTaskProperty，可复用。
2. **modelValue 类型**：`number[]`（ID 数组）+ `change` 事件带完整用户对象。
3. **筛选交互**：组织树和角色列表均支持多选 checkbox，合并 OR 查询用户。
4. **全局搜索**：顶部搜索忽略左侧筛选，全局查；回车+按钮触发，非防抖。
5. **已选同步**：右栏 × 删除 + 中栏待选区同步勾选状态，双向同步。
6. **后端改造**：`UserQueryRequest` 加 `orgIds`/`roleIds` 数组 + 新增批量查接口。
7. **旧数据**：`designerStore` 直接改 `value:string` → `userIds:number[]`，不兼容。
8. **初始状态**：打开弹窗时待选区显示空态提示，不预加载全部用户。
9. **角色加载**：`getRoleList({size:999})` 一次性拉，组件内缓存。
10. **搜索触发**：回车+按钮，非防抖自动。
