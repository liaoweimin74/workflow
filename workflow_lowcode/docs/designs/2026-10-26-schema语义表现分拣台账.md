# Schema 语义/表现分拣台账（design D11 · multi-client-support Task 10）

> **用途**：P2「端渠道 profile 覆盖层」（plan Task 14）与 schema 校验器拦截清单的**唯一输入**。
> 对存量 VIEW 页面配置与 form-create 表单 schema 逐键分拣：语义（跨端共用，留 schema）
> vs 表现（端相关，迁入渠道 profile 或由渲染器忽略）。
>
> **数据口径**：`workflow_v6` 库实测扫描（2026-10-25），脚本
> `backend-node/tools/schema-audit.ts`（只读遍历 `wf_page_def.schema` / `wf_form_def.schema`，
> 注意列名是 `schema` 非 config_json）。复现：
>
> ```powershell
> cd workflow_lowcode/backend-node; pnpm exec tsx tools/schema-audit.ts > $env:TEMP\schema-audit.json
> ```
>
> **样本量**：VIEW 页面配置 5 份（共 6 行，1 行 schema 为空）；form-create 资产 6 份（9 行中 3 份非数组/空）。
> **分类判据**：
> - **语义** = 决定取什么数据、做什么动作、什么校验（字段/匹配/权限/流程/绑定）→ 跨端一致，留 schema；
> - **表现** = 决定 WEB 上怎么摆（尺寸/列宽/对齐/可见性/弹窗大小）→ 移动端布局独立，迁渠道 profile 或渲染器忽略；
> - **待议** = 双面性（形式影响交互范式或数据窗口）；
> - 处置 = `迁入渠道 profile`（存在合理端差异且用户可按端配置）/ `渲染器忽略`（仅 WEB 有意义，其他端渲染层直接不读）/ `保留`。
>
> ⚠️ 粗筛正则（width|height|span|offset|align|hidden|show…）只是提示，**漏网与误报已在下表人工复核列**
> （如 `actionColumnWidth`、`display` 未命中；`_fc_id` 命中不了也不属于表现）。

## 4. 设计器侧扩展点调研（拦截位置草图 · Task 14 输入）

两个 schema 写入入口 + 一个服务端复查口：

- **入口 A · VIEW 页面**：`frontend/src/views/page/PageDesigner.vue` `handleSave()`（≈L1847）
  序列化 schema 处。上游是各配置面板（QueryColumnsConfig / ColumnAdvancedConfig /
  ActionsConfig / CardStyleConfigDialog / FilterConfig…）。拦截形态：
  保存前对 schema 跑「表现键清单」匹配器 → 命中键改写进
  `channelProfiles[端渠道类型]` 覆盖层（表现值不再直留主 schema），或提示迁移。
- **入口 B · form-create 表单**：`frontend/src/views/form/FormDesigner.vue` `handleSave()`（L787，
  `designerRef.getRule()` 序列化处）。现成遍历设施 `src/views/form/schemaRules.ts` 的
  `walkRules()`（已兼容 children / props.rule 双嵌套形态）可直接复用做逐节点键检查。
- **服务端复查口**：`wf_page_def` / `wf_form_def` 保存 API 落库前同规则校验（防直连 API 绕过设计器）；
  与前端共享同一份清单常量（建议由本台账固化为 `channel-schema-policy` JSON 模块，前后端各自引用）。
- **消费端**：渲染器（PageDataTable / PageDataCards / FormRenderer）读 `channelProfiles[当前端]`
  覆盖表现值；无覆盖走 WEB 原值 = 零破坏。移动端渲染层对「渲染器忽略」类键天然不读。

## 5. 结论与规模判断

- 存量表现键**总量极小**（实例 ≤12），拦截清单可枚举，P2 覆盖层按「迁入 profile / 忽略 / 保留」
  三值处置即可执行；语义键零改动承诺成立（schema 主体不动，端差异全在覆盖层）。
- 数据面补充：真实库仅 workflow_v6 的 5+6 份资产（演示集），出码链路的 `wf_form_def.column_config`
  与模板 schema（templateSchema.ts）不在本次审计口径——Task 14 若扩面，先跑同一脚本改表名即可复用。

**扩面新结论（本台账此前未覆盖的键）**

1. **页面 rule 树面**（平铺 §1 之外，出码真正消费的 rule[]）：新落出的桌面表现键
   `props.style`（input/datePicker 内联样式）、`props.dialogWidth/dialogHeight/inlineHeight`、
   `props.border/stripe/stretch/actionColumnWidth`（page-table EP 皮肤）、布局表格
   `props.columns` 几何 → 全部**表现 · 移动端忽略**；`props.pageSize/pageSizes`、
   `props.displayMode/formMode/type`（容器形态）→ **待议 · 迁渠道 profile**；
   `props.dataSourceId/selectionMode/viewActions/viewEvents/recordLocator/show*Button` 等
   → 语义保留；`props.designMode` 并入设计器管理键。
2. **column_config 面（7 份实扫）**：12 键（key/label/columnType/length/scale/unique/indexed/
   required/componentType/hidden/pickerConfig/subColumns）**全为数据模型约束或端无关声明，
   零 WEB 布局专属键**——数据模型面天然端无关，移动出码按 componentType 走端控件映射即可，
   该面无迁移无忽略工作量。
3. **平铺 VIEW 面**：不在出码输入面（`parse.ts` 只消费新式 `{rule,option,dataSources,actions}`），
   §1 分拣结论仍入表——服务端复查口（§4）与存量形态迁移判定共用同一清单。

**闭环判据复核**：`auditInventoryCoverage(快照).uncovered === []`（测试锁定，12/12 绿）；
`validatePolicyIntegrity()` 违例为空（表内无「表现+keep」自相矛盾）；重跑 `schema-audit.ts`
