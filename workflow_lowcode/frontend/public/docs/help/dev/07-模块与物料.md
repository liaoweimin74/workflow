# 07 模块与物料

模块和物料解决同一类问题——「做好的东西怎么复用」，但粒度和场景不同：

| | 模块 | 物料 |
| --- | --- | --- |
| 粒度 | 一组应用资产打包（表单+页面+数据源+逻辑流+流程） | 单个页面或单个组件 |
| 载体 | zip 文件，导出/导入 | bundle + manifest 文件，上传/引用 |
| 典型场景 | 开发 → 测试 → 生产环境迁移；同类客户快速复制 | 精心打磨的看板页/小组件跨项目共享 |

## 7.1 模块：打包迁移

入口：**开发管理 → 模块管理**。

![模块管理：导出与导入](images/module-list.png)

页面分**导出模块**与**导入模块**两块：

- **导出**：勾选要打包的资产（要求已发布的业务表单、页面、数据源、逻辑流、工作流），平台先做依赖闭包分析（把被引用的资产一并带上）再打包生成模块 zip；导出时填写模块名称、标识与描述。
- **导入**：目标环境上传 zip → 预检（列出与现有资产的同名冲突）→ 逐条选择「覆盖 / 跳过」→ 执行导入。

注意事项：

- 依赖是被完整打包的。若目标环境已有同名但内容不同的资产，覆盖会影响正在使用它的页面，预检页务必逐个确认；
- 导入后请复核菜单挂接与角色授权（授权关系默认不随模块迁移）；
- 建议一次模块对应一个完整业务功能（如「设备报修模块」），小而清晰比大而全好维护。

## 7.2 物料：页面与组件的复用件

入口：**开发管理 → 物料管理**。

![物料管理列表](images/material-list.png)

工具栏从左到右：

- **上传物料**：提交 `bundle.js` + `manifest.json` 两个文件（需 `material:manage` 权限）；
- **导出选中**：勾选若干物料导出为 zip，供其他项目导入；
- **导入物料包**：上传导出的 zip，先出预检表（全新 / 已存在 / 不可导），冲突条目逐条选覆盖或跳过；
- **下载工程模板**：得到 `material-scaffold` 脚手架工程，本地改造后构建再上传。

列表列：名称、标识（key）、类型（页面 PAGE / 组件 WIDGET）、版本、SDK 版本、启用状态；行操作含打开、停用、挂到菜单、删除。

物料分两型：

- **页面型（PAGE）**：整页产物，挂到菜单即可当页面用（样例菜单里的「示例物料看板」就是页面物料）；
- **组件型（widget）**：单个组件，会出现在页面设计器的组件面板里（分组在内置组件之后，名称带 `material:` 前缀），可拖入任意自定义页面复用。

### 制作物料

物料产物由 `material-scaffold` 脚手架工程构建得到两个文件——bundle（产物）与 manifest（元数据，含名称、key、可配置字段声明），上传时两个文件一起提交：

- 页面型：`pnpm build`（产物在 dist/page）；
- 组件型：`pnpm build:widget`（产物在 dist/widget）。

组件型物料可在 manifest 中声明**可配置字段**（支持文本、数值、开关、下拉、多行文本），使用方把组件拖进页面后，在属性面板按这些字段配置（如标题、刷新秒数、主题），平台自动渲染配置表单。手写 Vue 物料的工程结构、manifest 写法与构建命令，以仓库根的 `material-scaffold` 脚手架工程及其示例为准确。

### 版本与删除

- **同 key 覆盖上传会把版本 +1，旧 bundle 立即失效**——升级前先确认所有使用方已刷新/验证；
- 删除物料时平台会检查菜单引用：被引用的物料删除会留下无效菜单，需手动清理，弹窗中会列出引用菜单清单。

## 7.3 常见问题

**Q：模块和物料都能搬页面，用哪个？**
成建制的业务功能（含表、流程、逻辑）用模块；单个精致的展示件（一个看板、一个倒计时组件）用物料。

**Q：物料页面能改吗？**
物料是黑盒产物，平台内不能进设计器编辑；要定制就复制其思路用自定义页面重搭，或修改物料源码工程重新构建上传。

**Q：导入模块后用户看不到功能？**
模块迁移不带菜单授权（部分入口菜单也可能未挂接），到菜单管理确认入口、到角色管理补授权，见 [08 权限与菜单](08-权限与菜单.md)。
