# 05 流程运维

管理员在流程侧的日常：监控实例、支撑审批人、处理卡单。开发侧（画流程、配节点）见开发手册 [05 流程编排](../dev/05-流程编排.md)。

## 5.1 流程中心（流程管理 → 流程中心）

全部流程实例的监控视图：

- 按流程定义、状态、时间筛选，找到目标实例；
- 进入**实例跟踪页**：流程图高亮当前节点、查看各节点的办理人、意见与时间线；
- 实例详情可核对表单填报内容，作为与业务方对账的依据。

## 5.2 待办处理（流程管理 → 待办处理）

管理员自己的待办事项。管理员以普通审批人身份参与的流程也在这里处理，操作与其他用户一致：通过、驳回、加签、转签、填写意见。

**代审的边界**：平台没有内置的「替他人审批」开关；确需某人离岗期间的审批连续性，正确做法是提前在流程设计上兜底（审批人设为角色而非个人，或允许发起人调整审批人），由管理员协调相关角色成员补充。

## 5.3 卡单的常规处理

「流程卡在某节点」多数是审批人缺位或不在线：

1. 跟踪页确认卡在哪个节点、解析出的审批人是谁；
2. 审批人存在但不在线 → 站内信/短信催办（发消息给该用户）；
3. 审批人解析为空（离职、角色空）→ 管理员补角色成员（见 [01 章](01-用户与角色.md)/[02 章](02-组织架构.md)）；该实例的存量审批人是否可补，取决于流程设计的「无审批人策略」与节点是否允许转签；
4. 常态化缺人 → 让开发侧调整该节点的审批人来源后部署新版本。

需要**终止、回滚实例**这类强干预时，当前版本由平台开发在引擎层处理，请联系并说明实例 ID 与预期结果。

## 5.4 草稿箱

个人功能（发起前暂存的单据），管理员仅在自己视角使用；业务方反馈「发起的单不见了」时先查草稿箱。

## 5.5 每日巡检建议

- 流程中心按「进行中」过滤，扫一遍长期停留的实例（超过业务时效的）；
- 结合消息管理 → 发送记录，确认催办/通知渠道是否健康；
- 常卡单的节点反馈给开发侧调整审批人策略，从源头减少人工干预。
