# 01 平台介绍

## 1.1 平台是什么

本平台是一个「低代码 + 工作流」应用搭建平台：开发者不需要写前后端代码，通过可视化配置即可完成数据建模（表单）、界面搭建（页面）、流程审批（工作流）、自动化逻辑（逻辑流），并由统一的用户/角色/菜单体系控制谁能看到什么、能做什么。

适合搭建的典型应用：各类审批流（请假、报销、采购）、台账与填报系统、查询与看板页面，以及它们的组合。

## 1.2 核心概念

理解下面这几个概念（以及它们之间的关系）就理解了平台：

| 概念 | 一句话解释 | 管理入口 |
| --- | --- | --- |
| **业务表单** | 定义「数据长什么样」。设计字段并发布后，平台自动生成业务数据表来存数据 | 开发管理 → 表单列表 |
| **工作流表单** | 流程发起人填报的表单，数据落在流程实例里，不单独生成业务表 | 开发管理 → 表单列表 |
| **页面（自定义页面）** | 给用户操作的「界面」。当前新建页面统一为自定义页面，由数据表格、卡片、图表、表单容器等组件拼成 | 开发管理 → 页面列表 |
| **视图（存量）** | 早期形态的列表查询页面（勾选筛选列/展示列/操作按钮即成页）。存量视图仍可用，新建不再产生 | 开发管理 → 页面列表 |
| **数据源** | 页面组件「从哪里取数」的统一抽象。支持五种类型：业务表单（FORM）、工作流表单（WORKFLOW）、系统内建（SYSTEM）、SQL、第三方 API | 开发管理 → 数据源管理 |
| **逻辑流** | 拖节点拼出来的服务端自动化流程：调接口、读写数据、发通知、调 AI 等 | 开发管理 → 逻辑流 |
| **工作流** | BPMN 标准的审批流程图：发起、审批、会签、驳回、超时等 | 流程管理 → 流程定义 |
| **菜单** | 功能的「入口」和「可见性开关」。每个功能要挂到菜单上，用户才能看到 | 开发管理 → 菜单管理 |
| **角色** | 一组菜单/按钮权限的打包，用户通过角色获得权限 | 系统管理 → 角色管理 |
| **模块** | 把做好的表单、页面、数据源、逻辑流、工作流打包成 zip，导出后可在另一个环境导入复用 | 开发管理 → 模块管理 |
| **物料** | 可复用的整页（页面物料）或单个组件（组件物料），跨项目、跨环境复用 | 开发管理 → 物料管理 |

它们的关系（开发主线）：

```
业务表单 ──发布──▶ 数据表 ──包装──▶ 数据源 ──绑定──▶ 页面组件 ──挂接──▶ 菜单 ◀──授权── 角色 ◀── 用户
                                    ▲                │
工作流表单 ──流程定义绑定──▶ 工作流 ◀┘   事件触发 ──▶ 逻辑流（自动化）
```

## 1.3 菜单地图

登录后左侧菜单按用途分为几个区：

| 一级菜单 | 二级项 | 面向 |
| --- | --- | --- |
| 首页 | — | 所有人（默认仪表盘；可在页面列表把其他已发布页面设为首页） |
| **开发管理** | 菜单管理、表单列表、页面列表、数据源管理、逻辑流、模块管理、物料管理 | 开发者 |
| **样例页面** | 各类组件演示页（数据详情与步骤条、卡片列表、物料看板等） | 开发者学习参考 |
| **系统管理** | 用户管理、角色管理、组织机构、字典管理、岗位管理、成员组管理、模型配置 | 管理员（见管理手册） |
| **流程管理** | 流程定义、流程中心、草稿箱、待办处理 | 流程设计 + 日常审批 |
| **消息管理** | 消息中心、模板管理、渠道配置、订阅规则、发送记录、公告管理、事件管理 | 管理员（见管理手册） |

> 不确定某功能在哪时，可用顶部「搜索/面包屑」逐级找；开发类入口已全部收拢到「开发管理」目录下。

## 1.4 设计器一览

平台共有五个可视化设计器，界面布局类似：左侧/上方是组件或节点面板，中间画布，右侧属性面板。

| 设计器 | 用途 | 打开方式 |
| --- | --- | --- |
| 表单设计器 | 拖拽字段设计表单 | 表单列表 → 某表单 → 设计 |
| 页面设计器（PageDesigner） | 拖拽数据组件搭建自定义页面 | 页面列表 → 某页面 → 设计 |
| 流程设计器（BPMN） | 编排审批流程图 | 流程定义 → 新建/编辑 |
| 逻辑流设计器 | 编排自动化逻辑 | 逻辑流 → 新建/编辑 |
| 菜单管理 | 维护菜单树 | 开发管理 → 菜单管理 |

## 1.5 权限的基本逻辑

平台采用「菜单 + 按钮」两级功能权限：

- 用户 → 角色 → 勾选菜单/按钮权限项；
- 页面对普通用户可见的前提：他所属角色被授予了对应菜单；
- 自定义页面的访问受双重校验：前端按菜单权限控制入口可见性，后端对渲染与数据接口再校验一次（详见 [08 权限与菜单](08-权限与菜单.md)）。
