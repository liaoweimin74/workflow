     1→# REST API 面盘点（Spring Boot → Node.js 迁移基线）
     2→
     3→> Task ID: 13-1a · 生成方式：静态扫描 `backend/src/main/java/com/workflow/` 下全部 39 个 `@RestController` 源码逐个提取。
     4→> 统计口径：一个 Java 方法上的一个 HTTP mapping 注解 = 1 个端点。
     5→
     6→## 0. 全局约定
     7→
     8→### 0.1 Base URL
     9→
    10→| 项 | 值 | 来源 |
    11→|---|---|---|
    12→| 协议/主机/端口 | `http://localhost:8080` | `application.yml` → `server.port: 8080` |
    13→| Context-Path | **无**（根路径直接挂 `/api/...`） | `application.yml` 未配置 `server.servlet.context-path` |
    14→| 全局路径风格 | `/api/v1/**`（业务）、`/api/**`（system 域无 v1） | 各 Controller 类级 `@RequestMapping` |
    15→
    16→### 0.2 鉴权方式
    17→
    18→- **JWT Bearer Token**：请求头 `Authorization: Bearer <accessToken>`（`GlobalConstant.TOKEN_HEADER/TOKEN_PREFIX`）。
    19→- `JwtAuthenticationFilter`（OncePerRequestFilter）解析 token → 校验 `tokenType == access_token` → 按 `userId` 加载 `LoginUser`（含角色权限集合）写入 SecurityContext。
    20→- Token 有效期：access 30 分钟 / refresh 7 天（`GlobalConstant`）；refresh token 端点 `POST /api/auth/refresh`。
    21→- **无 Spring 表达式注解鉴权**：全代码库 **0 处** `@PreAuthorize` / `@HasPermission`（`HasPermission`/`PermissionEvaluator` 框架类存在但仅被 `PageAccessGuard` 程序化使用）。实际鉴权手段：
    22→  1. SecurityConfig 路径级：除 2 条 permitAll 外全部 `authenticated()`；
    23→  2. 通知管理端：`NotificationAdminAuthorization.requireAdmin()`（代码内硬校验角色 `ROLE_ADMIN` 或 `admin`，否则抛 `BusinessException(403)`）；
    24→  3. 页面数据出口：`PageAccessGuard.assertPageAccess(pageKey)`（菜单权限 `page:read:{key}`；无菜单→404，无权限→403；admin 自动放行）。
    25→
    26→### 0.3 放行路径（permitAll，SecurityConfig）
    27→
    28→| # | Pattern | 方法 | 说明 |
    29→|---|---|---|---|
    30→| 1 | `/api/auth/login` | 全部（实际仅 POST） | 登录 |
    31→| 2 | `/api/v1/notifications/sse` | 全部（实际仅 GET） | SSE：浏览器 EventSource 无法带 header，靠 `?token=` query 自行认证 |
    32→
    33→其余 `anyRequest().authenticated()`。CSRF 关闭、Session STATELESS。
    34→
    35→### 0.4 多租户
    36→
    37→- `TenantInterceptor`（WebConfig 注册，作用于 `/api/**`）：读请求头 **`X-Tenant-Id`** 写入 `TenantContext`，请求结束清理。租户头**可选**，业务层按需强制（如 `ProcessDefinitionController.listVersions`、通知管理端均取 `TenantProvider.getTenantId()`）。
    38→
    39→### 0.5 CORS（CorsConfig）
    40→
    41→`CorsFilter` 注册在 `/**`：`allowCredentials=true` + `allowedOriginPattern("*")` + 所有 header/method，`maxAge=3600`。Node 版需等价放开。
    42→
    43→### 0.6 统一响应封装
    44→
    45→| 封装 | 结构 | 使用范围 |
    46→|---|---|---|
    47→| `R<T>` | `{code:int, msg:string, data:T}`；成功 code=200；失败如 400/401/403/404/429/500 | **全部端点**（除 SSE 返回流） |
    48→| `PageResult<T>` | `{total, page, size, rows[]}`（1-based） | system 域用户/角色/字典分页、通知用户端消息列表、通知事件列表 |
    49→| `PageResponse<T>`（api/dto） | `{content[], pageNumber, pageSize, totalElements, totalPages}`（1-based） | api 域流程/表单/页面/数据源分页 |
    50→| `BizDataPageVO` | `{records[], total, page, size}` | 业务数据 biz-data、数据源 data、internal 部门树/用户分页 |
    51→| 裸 `Map` | `{rows[], total, page, size}` | 通知管理端 subscriptions/announcements/deliveries 列表 |
    52→
    53→⚠️ 迁移注意：**三种分页字段名并存**（rows/content/records），前端依赖各自字段，需逐一保真。
    54→
    55→### 0.7 错误处理
    56→
    57→- `GlobalExceptionHandler`（`@RestControllerAdvice`）+ `BusinessException(code, msg)`；`R.fail(...)` 也在业务内直接返回（404/429 等）。HTTP 状态码与 `R.code` 不完全一致（业务错误多以 200 + R.code 表达），Node 版需对齐前端判断逻辑。

   528→## 6. 迁移关键注意点
   529→
   530→1. **SSE 是唯一非 JSON 端点**：`GET /api/v1/notifications/sse`（produces text/event-stream，返回 SseEmitter 长连接），permitAll + `?token=` query 认证且强制 access_token 类型；Node 版需实现等价 SSE 通道（事件如 `new-message`），并处理连接注册/推送/断连。
   531→2. **放行路径仅 2 条**：`POST /api/auth/login` 与 SSE 端点；其余全部需 JWT。且全库无 `@PreAuthorize`——管理端权限是代码内 `requireAdmin()`、页面数据出口是 `PageAccessGuard`（404/403 语义 + admin 放行），Node 版必须以中间件复刻这两类检查，不能只做"登录即可"。
   532→3. **响应/分页封装不统一**：所有端点包 `R{code,msg,data}`；分页有三种形态（`PageResult.rows` / `PageResponse.content` / `BizDataPageVO.records`，通知管理端列表为裸 `Map.rows`）；错误码常见"HTTP 200 + R.code=4xx/5xx"。前端按字段取值，Node 版需逐端点保真。
   533→4. **隐式契约多**：`X-Tenant-Id` 头（可选，`/api/**` 拦截器透传）；`BizDataQueryRequest`/`UserQueryRequest` 等 GET 端点用**无注解 POJO 绑定 query 参数**（含 `filter`/`params` JSON 字符串）；乐观锁 `version` 藏在 body Map 或 query；`POST /notifications/read-batch` body 直接是 `List<Long>`；`claim` 的 userId 走 query 而 complete/reject 走 SecurityContext。
   534→5. **多 Controller 共享前缀、路径有重叠风险**：`/api/v1/process-instances`（3 个 Controller）、`/api/v1/tasks`（2 个）、`/api/v1/pages`（3 个）、`/api/v1/data-sources`（3 个含 db/explore 子前缀）。存在多段路径防冲突设计（如 `/key/{key}/versions`、`/versions/{procDefId}/editor`），路由注册顺序在 Node（Express 等）下需保持"具体路径优先于 `/{id}` 参数路径"。全库无文件上传端点（0 处 MultipartFile）。
