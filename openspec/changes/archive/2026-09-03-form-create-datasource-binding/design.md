## Context

项目在 `frontend/src/vendor` 自有封装层中集中维护 form-create 设计器规则，现有选项规则支持静态、文本、JSON 和远程 API 四种方式。项目同时已有 FORM、SYSTEM、API、WORKFLOW 数据源查询能力，以及 DataPicker/LookupPicker 的绑定配置与运行时取数逻辑。

约束是不修改 form-create 依赖源码。扩展必须发生在项目自己的规则工厂、配置组件、注册入口和渲染适配层，并且保存后的 schema 需要在设计器预览、正式表单渲染和重新编辑时保持一致。

## Goals / Non-Goals

**Goals:**

- 在选项数据配置中增加“数据源”类型和“配置数据源”入口。
- 复用 DataPicker/LookupPicker 的数据源选择、过滤和字段元数据能力。
- 支持 FORM、SYSTEM、API、WORKFLOW 数据源，并允许配置查询条件和 label/value 字段映射。
- 普通选项、树形/级联选项和穿梭框都能消费转换后的选项数据。
- 数据源未绑定时完整保留原有四种选项配置行为。

**Non-Goals:**

- 不修改 form-create 包源码或其上游组件实现。
- 第一版不新增数据库、后端数据源类型或自定义 JavaScript 转换函数。
- 第一版不改变数据源的权限、分页协议和 CRUD 语义。

## Decisions

### 配置模型与规则扩展

在项目自有的 `makeOptionsRule`/树形选项规则中加入 `datasource` 类型。数据源绑定保存为独立的 effect/schema 节点，不复用 `effect.fetch` 的 HTTP 配置，避免把数据源标识和查询语义编码为 URL。已有选项类型继续使用各自原始字段。

### 配置界面复用

选项数据选择“数据源”后，通过“配置数据源”按钮打开独立弹窗。弹窗固定包含两个页签：“数据源”页签复用数据表格组件使用的 `DsBindingConfigDialog` 数据源配置代码，包含数据源选择、metadata 加载和查询条件配置；“字段配置”页签不使用表格，只使用四个下拉框配置显示字段、值字段、子节点字段和父节点字段。字段候选项来自所选数据源的 metadata。

### 运行时取数

运行时检测到有效 datasource 配置后，调用现有前端数据源查询 API，按字段配置页签保存的映射把记录转换为组件需要的选项。普通选项输出 `{label, value}`；树形选项额外应用父子节点/children 映射。请求状态、空结果和错误提示遵循数据表格数据源绑定现有约定。

### 优先级与兼容性

同一规则选中 datasource 时，数据源结果优先；未选中 datasource 时走原有 options/effect.fetch 路径。配置切换时清理不再适用的 datasource 状态，避免旧绑定意外覆盖静态或远程配置。子节点字段与父节点字段不能同时保存为有效值。

### 备选方案

后端专用选项 API 能集中权限和转换，但会扩大范围；把数据源编译为远程请求则模型不自然且难复用现有绑定逻辑。因此第一版采用前端扩展，并继续使用后端已有统一数据源 API。

## Risks / Trade-offs

- [配置组件存在重复逻辑] → 复用 `DsBindingConfigDialog` 的数据源页签或抽取最小共享子组件，禁止再复制一份完整数据源配置表单。
- [不同数据源返回结构不一致] → 统一通过现有查询 API 的记录列表，并强制要求显式 label/value 字段映射。
- [级联数据层级表达不同] → 配置中明确 children/parent 字段；普通列表和树形列表分别校验必需映射。
- [设计器预览与正式渲染不一致] → 共用同一个 datasource resolver，并覆盖保存、重新加载、预览和正式渲染测试。
- [数据量过大导致选项加载慢] → 第一版沿用现有查询分页限制；不在本变更中引入无限滚动或缓存策略。

## Migration Plan

这是向后兼容的前端 schema 扩展，无需迁移已有表单数据。发布顺序为：共享配置/解析能力、规则与配置界面、运行时消费、测试。回滚时移除新前端 bundle 即可；已有 schema 中不存在 datasource 节点，因此仍按旧逻辑运行。

## Open Questions

- 具体数据源查询 API 的返回字段和分页参数应以现有 `dataSourceApi` 与 DataPicker 实现为准。
- 树形/级联选项的默认父子字段是否能从元数据推导，需在实现阶段结合现有列元数据确认。
