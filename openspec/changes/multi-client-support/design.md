## Context

**平台现状（单端假设贯穿全链路）**：

- 前端路由静态注册（`frontend/src/router/index.ts`）+ `sys_menu` 数据树双轨制；菜单只决定侧边栏显隐与权限码，页面渲染权走 `page:read:{key}` 挂接 + 后端 `PageAccessGuard` 双重校验
- 全局只有**一棵菜单树**，0 目录/1 菜单/2 按钮三层；V58 归位后顶层为：首页/开发管理/样例页面/系统管理/流程管理/消息管理
- 运行态只有 PC Web 管理端一个"端"；表单/页面 schema 由 Element Plus 桌面组件集渲染，混有桌面渲染细节（列宽、栅格 span、弹窗尺寸）
- 端侧唯一先例：小程序（V64 `sys_user_openid` + `/api/auth/miniprogram/login|bind` + ROLE_CUSTOMER），"身份绑定式"特例，未泛化
- 数据范围 v3（V65）：受控数据源 × grant（权限对象 × 主体）**只管行**
- 后端 `ChannelType` 是消息通知通道（站内信/短信），与交付终端无关——命名需在模型中区分
- `CodegenLab` 出码线已验证 .vue 产物路线

**需求形状**：任意业务系统"一套业务模型、N 客户端 × M 渠道（WEB/H5/APP/小程序）"。平台端/司机端/乘客端只是举例，**端集合开放**——新增一个端 = 配置 + 发布动作，不改平台代码。

**约束**：存量迁移零破坏（path/权限码/授权不动）；单 Web 服务器同源部署；角色跨端必须强隔离（非白名单）；脱敏必须在服务端生效。

**干系人**：平台建造者（开发管理操作者——建端→配渠道→设计→发布→挂菜单闭环的主体）、业务端最终用户（司机/乘客等）、平台运维。

## Goals / Non-Goals

**Goals:**

1. Client / Channel 成为数据模型与基础设施能力（`sys_client` / `sys_client_channel`），管理界面 A1/A2 落地于开发管理
2. 菜单按端分树（`sys_menu.client_id`），形态按渠道类型约束（WEB 三层树 / 移动端底部 Tab 2~5 + 工作台宫格），存量 100% 回填默认平台客户端
3. 角色挂单一端（`sys_role.client_id`），登录链路校验请求端与角色所属端一致，隔离边界绝对清晰
4. 身份认证泛化（P1）：V64 openid 绑定抽成通用"端身份"，token 携带 client/channel 上下文，登录方式按端×渠道配置
5. 字段级数据范围（P1）：数据范围 grant 增加字段策略（可见/脱敏/隐藏），在服务端序列化层生效，一次封堵详情/导出/开放 API 三条泄漏路径
6. 单一逻辑 schema + 渠道模板映射 + 端覆盖层（P1）：桌面 Element Plus / 移动 uni-app 内置组件两列渲染器；H5 工作台（B1）端到端可用
7. 按渠道交付制品（P2）：APP 原生壳 + JSBridge 复用 H5 渲染器；uni-app Vue3 运行时壳小程序（schema 解释器）；发布管线按端出包
8. P0 前置 spike：存量 schema 语义/表现字段审计，为渲染分层铺路

**Non-Goals:**

- 出码编译投放（schema → 端工程产物）与预览混轨——出码线（CodegenLab）保持独立用途
- 自定义脱敏规则引擎——仅平台内置规则集（手机/姓名/身份证/车牌/地理泛化），防配置面成为泄漏面
- 新建一级目录「端接入管理」——新页面 <3 个不立目录；后续超过 3 页再升级（只挪 parent_id，path 不动）
- 权限码加端前缀、存量菜单 path/权限码/授权变更——全部不动
- 消息通知通道（`ChannelType`）改造——与交付终端是两个概念，仅命名区分

## Decisions

**D1. Client/Channel 为数据实体，非枚举**
`sys_client`（name/code/logo/status）1─N `sys_client_channel`（channel_type: WEB/H5/APP/MP + 开通开关 + 渠道参数 appid/secret/最低版本等）。端集合开放扩展。
- 备选：代码枚举固定端 → ✗ 与"新增端不改代码"的需求形状直接冲突。

**D2. 存量菜单树整体归默认平台客户端**
迁移只加 `sys_menu.client_id` 列 + 存量回填；path、权限码、角色授权、历史页签一律不动。平台端自此是众多 Client 的普通实例，无特殊代码路径。
- 依据：V58 归位先例已验证此类迁移成本极低。

**D3. 端菜单形态 = 同一棵树的两种映射**
WEB/管理端保持目录→菜单→按钮三层（现状规则）；H5/APP/小程序端为**底部 Tab（前 2~5 个一级菜单）+ 工作台宫格（其余节点）**，工作台内 ≤2 层；按钮节点跟随菜单、不占屏。服务端按端形态校验拖拽落点合法性。
- 备选：移动端独立菜单表/两套数据 → ✗ 双树必然漂移。

**D4. 客户端管理归开发管理；菜单管理加端作用域 Tab**
A1/A2 新页面 `/system/client`（V66 口径：按"哪拨人干什么事"归目录，不按实体作用域；path 与权限码命名空间不随目录走）。A3 在现有菜单管理页顶部加"端"切换，不另立"客户端菜单管理"页。A5 复用发布对话框加"目标端"勾选，A4 复用用户详情加"端身份"Tab——能并入现有页的不建新页。

**D5. 能力被引用而非复制；隔离靠两道闸**
`wf_page_def ──< page_client_target >── sys_client` 资产发布范围 × 端树挂接。司机端"待办"是引用同一套流程 API 的移动形态新页面，不是共享 PC `/process/todo`。`PageAccessGuard` 校验粒度升级为 (client, page)，与现状双重校验语义一致。
- 备选：菜单节点跨端共享引用 → ✗ 一份 PC 页面塞进移动端形态，渲染适配复杂度爆炸。

**D6. 角色挂单一端（强隔离），非 N:N 白名单**
`sys_role.client_id` NOT NULL，存量回填平台端；一个角色记录恰好归属一个端。跨端通用人员 = 每端各授。登录链路校验请求端与角色所属端一致，不一致 = 该端无角色（菜单空 + API 403）。
- 备选：角色 × 允许端白名单 → ✗ 配错即越权；本方案错误语义是"无权限"，不存在越权缝隙。

**D7. 脱敏 = 数据范围 grant 的字段策略，服务端序列化层生效**
grant 在"行"之上增加字段策略：列 → 可见 / 脱敏（引用内置规则）/ 隐藏；缺省跟权限对象基线。生效点在查询结果 → 渲染/数据/导出 API 出口前，**不在 SQL 列选**——一次封死详情、导出、开放 API 三条泄漏路径。

**D8. Schema 三层分界：语义进 schema、布局进端覆盖层、交互骨架进渲染器框架**
- 组件集（渲染器级）：schema 只记语义类型，两套渲染器按渠道模板映射（select→picker、table→卡片列表、弹窗→全屏页…）
- 布局（配置级）：端覆盖层按渠道存，移动端只做**列→卡片槽位、字段显隐、排序**三件事，缺省自动映射
- 交互骨架（框架级）：弹窗→页面、工具栏→底部栏，不进 schema
- 备选：同 schema 响应式自适应 → ✗ 表格塞不进 375px，伪移动端；分端两套资产 → ✗ 双份维护必然漂移。

**D9. 移动渲染器 = uni-app Vue3 内置组件；不引入 Vant；映射表收敛两列（EP/uni）**
实测查证（设计文档 §5.2）：Vant 4 仅 Web（操作 DOM），小程序不可用（`@vant/weapp` 是另一套 WXML 规范）；uni-app/Taro 是项目级编译管线，无法在管理端运行时挂载预览（Taro blended Vue3 有未解决 issue #16418）。
采用：uni 内置组件同一渲染器经 `dev:h5`（喂 H5 与 APP 壳）+ `dev:mp-weixin`（"schema 解释器"小程序运行时壳）覆盖三端，运行时渲染单一模型；`[桌面] [移动]` 预览切换在管理端 iframe 手机框内跑 H5 产物。
- 备选：Vant H5 + uni 小程序双列映射 → ✗ 双维护漂移；出码编译投放 → ✗ 预览=运行时 vs 产物=编译时双轨漂移。

**D10. 部署 = 单 Web 服务器同源共存**
`/` 管理端（Vue SPA）＋ `/m/` uni H5 产物（预览 iframe 与生产入口**一份产物两用**）＋ `/api` 后端；小程序包例外（经微信容器，只共后端）。注意：uni H5 路由 base 配 `/m/`、localStorage key 按端命名空间且登录态携带端上下文、`/m/*` SPA fallback。

**D11. P0 前置 spike：存量 schema 桌面细节审计**
现 VIEW 配置 / form-create rule 混有列宽、栅格 span、弹窗尺寸等表现字段。P0 先逐组件清点"语义 vs 表现"，表现字段迁到渠道 profile 层——否则移动渲染器被迫读不懂的遗留属性。spike 产出直接决定 D8 覆盖层的迁移清单。

## Risks / Trade-offs

- [存量 schema 混表现字段，渲染分层落空] → D11 spike 前置为 P0 任务；分拣结果迁渠道 profile 层，schema 校验器加拦截
- [部分语义组件无移动等价（富文本编辑、复杂透视表）] → 发布对话框（A5）标记"该端不支持"并拦截发布，不假装能渲染
- [角色挂端使多端通用人员授权成本上升] → 接受（错误语义清晰优先）；运维模拟入口列为 Open Question
- [登录链路泛化牵动全部现有端点] → P0 只做角色端一致校验最小切片（存量 token 默认平台端），P1 再泛化登录方式；分步不破存量会话
- [同源部署 localStorage/登录态串端] → key 命名空间 + token 端声明，方案见 Open Questions，P1 落地
- [uni 内置组件表现力上限 = 移动体验上限] → 混合方案的既定取舍：高频核心交互（司机接单/乘客地图）走原生壳 + JSBridge，schema 渲染不硬扛
- [小程序壳升级受微信审核约束] → 运行时壳（schema 解释器）把变更放服务端，壳本体低频出包（P2）
- [迁移列 NOT NULL 回填出错导致存量不可用] → Flyway 脚本带默认平台客户端 seed + 回填后核对查询（无 client_id 为空的行/角色），回滚 = 列增量可 drop

## Migration Plan

**数据库（Flyway，编号顺延 V65/V66 现状）**：

1. P0：建 `sys_client`（seed 默认平台客户端 `portal`）+ `sys_client_channel`；`sys_menu.client_id`、`sys_role.client_id` 加列回填 + 索引；`page_client_target` 建表（P0 建模即可，启用在 P1 发布联动）
2. P1：`sys_user_openid`/`sys_user_device` 端维度泛化；数据范围 grant 字段策略表
3. 每步迁移附核对查询；回填全程零 path/权限码变更，旧接口行为不变（缺省端 = portal）

**应用与部署**：

1. 后端 `PageAccessGuard` 升级 (client, page)：先兼容"请求无端上下文 → 按 portal 判定"发布，前端带端声明后收紧
2. `/m/` uni H5 静态站点 + nginx history fallback；预览 iframe 指向同源 `/m/preview`
3. 回滚策略：新增列/表均增量，可 drop 回退；渲染器与出包管线独立部署物，不触存量管理端

**分期交付判据**：P0 = 新建一个端不改平台代码，只走配置；P1 = 司机端类应用在 H5 端到端可用，跨端读数据受字段策略约束；P2 = 三渠道各自出包/发布。

## Open Questions

1. 运维"以某端身份查看"的模拟入口是否需要（角色挂端后跨端排查场景）——P1 前定
2. token 内 client/channel 声明的具体格式与多端会话策略——P1 设计细化
3. 同域部署多端 localStorage key 命名空间方案——P1 实现口径
4. 存量 schema 表现字段迁移清单——待 P0 spike 产出（D11）
