## Design Summary

BPMN 流程设计器，基于 bpmn-js + Vue 3 + Element Plus，独立配置表存储自定义节点属性，三栏布局（Palette / Canvas / Properties Panel）。分两阶段实现，第一阶段覆盖核心设计器功能。

## Alternatives Considered

### 方案 A：bpmn-js 原生（开箱即用）
- **做法**：直接使用 bpmn-js 默认 UI，包括默认的 properties panel
- **优点**：集成最快（5-7 天），无需自定义开发
- **缺点**：默认属性面板不支持自定义业务属性（审批人、表单权限、时限等），UI 风格工程化
- **为何未采用**：工作流节点有大量自定义业务属性，默认面板无法满足需求

### 方案 B：bpmn-js + 轻量定制（Agreed）
- **做法**：保留 bpmn-js 渲染引擎，完全重写属性面板（Element Plus），轻量视觉定制（配色、圆角、阴影）
- **优点**：BPMN 2.0 标准兼容性好，自定义属性灵活，视觉可做到现代美观
- **缺点**：比方案 A 多 1-2 周开发时间
- **为何采用**：平衡了开发效率与业务需求，性价比最高

### 方案 C：自研拖拽引擎
- **做法**：完全自建流程设计器，不依赖 bpmn-js
- **优点**：UI 完全可控，无框架限制
- **缺点**：BPMN 2.0 标准兼容需自行实现，工作量大（2-3 个月），维护成本高
- **为何未采用**：开发周期过长，BPMN 标准兼容风险高

## Agreed Approach

方案 B：bpmn-js + 轻量定制。bpmn-js 负责 BPMN 2.0 标准的渲染和 XML 序列化，属性面板完全用 Element Plus 重写，自定义属性通过独立配置表（wf_node_config）存储。视觉上改配色、圆角、阴影，不动底层 SVG 渲染器。

## Key Decisions

| 决策 | 结论 |
|---|---|
| 流程图引擎 | bpmn-js |
| 属性面板 | 完全重写，Element Plus |
| 自定义属性存储 | 独立配置表 wf_node_config（JSON 字段） |
| 视觉风格 | 轻量定制（不修改渲染器） |
| 部署方式 | 集成在现有前端，懒加载路由 |
| 阶段划分 | 第一阶段核心设计器，第二阶段增强功能 |
