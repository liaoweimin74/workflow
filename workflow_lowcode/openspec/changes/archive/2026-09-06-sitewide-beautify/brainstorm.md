# Brainstorm — 全站界面美化（参照音频后台仪表盘）

## Design Summary

对既有工作流管理系统（Vue 3 + Element Plus + Tailwind v4 + Pinia）进行全站视觉升级。
参照参考稿「音频类后台首页仪表盘」（uishijie.com/ui/11376.html）的**蓝紫 + 青科技感**浅色配色与卡片语言，
通过「全局设计令牌 + Element Plus 主题覆盖 + Tailwind v4 主题」让新风格全站自动生效，
再对布局框架（AdminLayout 侧边栏/顶栏/页签栏）与关键页面（登录页、仪表盘、列表/表单页、流程中心）做组件级精修。

核心目标：在不破坏 65+ 现有视图功能的前提下，将默认 Element Plus 外观升级为
「浅蓝紫底 + 靛蓝主色 + 青色点缀 + 柔和圆角卡片」的科技感后台风格，并保持暗色模式完整可用。

## Alternatives Considered

### 方案 A：全局主题层 + 关键页面精修（✅ 采用）
- **做法**：
  1. 更新 `DESIGN.md`：从参考稿程序化像素分析提取的配色令牌（背景 `#f1f4fe`、侧边栏 `#e6e9fb`、主色靛蓝 `#5755ee`、图表青 `#46c9d6`），建立完整 token 体系。
  2. 在 `style.css` 用 CSS 变量 + Element Plus 主题变量（`--el-color-primary` 等）覆盖全局，全站按钮/表格/表单/菜单/对话框自动换肤；同步扩展 Tailwind v4 `@theme`（新增 `indigo`/`cyan` 色系替代现有 `industrial`/`safety` 或并存）。
  3. 重构 `AdminLayout.vue`（侧边栏、顶栏、页签栏、右键菜单）与 `SubMenu.vue` 为参考稿风格的蓝紫科技感外壳。
  4. 重设计 `DashboardPage.vue`（统计卡片、欢迎横幅、图表占位）与 `LoginPage.vue`（品牌感登录）。
  5. 精选代表页面精修：列表页（表格/搜索区统一）、表单设计器入口、流程中心、个人中心。
  6. 暗色模式同步适配（现有 `.dark` 变量体系复用）。
- **优点**：一次性全局生效、可维护（单一 token 源）、不触碰业务逻辑、风险可控、符合专业工程实践。
- **缺点**：非逐页手写，个别页面细节可能不如逐页定制精细。
- **为何未采用**：见方案 B/C 取舍。

### 方案 B：字面逐页手写 65+ 个视图组件
- **做法**：对每个视图组件逐一重写样式。
- **优点**：每页可极致定制。
- **缺点**：工作量巨大、极易破坏业务功能、样式重复不可维护、回归测试成本极高。
- **为何未采用**：工程上不可行且用户已确认不选。

### 方案 C：仅布局 + 仪表盘（最小范围）
- **做法**：只美化 AdminLayout 与 DashboardPage，其余不动。
- **优点**：最快、最低风险。
- **缺点**：全站观感不统一，用户明确要求"全站美化"。
- **为何未采用**：范围不足，不符合"全站"诉求。

## Agreed Approach

采用**方案 A（全局主题层 + 关键页面精修）**：
以参考稿程序化提取的蓝紫+青配色建立 DESIGN.md 令牌体系，通过 `style.css` 的
Element Plus 主题变量 + Tailwind v4 `@theme` 实现全站自动换肤；
重构布局外壳（AdminLayout/SubMenu/页签）与登录/仪表盘等关键页面为参考稿风格；
暗色模式沿用现有 `.dark` 体系同步适配；全程保持业务逻辑零改动。

## Key Decisions

1. **配色来源**：参考稿像素分析（背景 `#f1f4fe`、侧边栏 `#e6e9fb`、主色 `#5755ee`/`#5452d3`、图表/点缀青 `#46c9d6`/`#48e0dd`、卡片白 `#ffffff`）。
2. **实现机制**：CSS 变量 + Element Plus 主题变量覆盖 + Tailwind v4 `@theme` —— 不逐页手写。
3. **主色迁移**：现有 `industrial`（#1a56db 蓝）迁移/并存为参考稿靛蓝 `#5755ee`；`safety`（琥珀 #f59e0b）降级为次要强调或替换为青色点缀。
4. **暗色模式**：保留，依据现有 `.dark` 变量体系做对应暗色令牌（深蓝紫底、亮青点缀）。
5. **范围分层**：L0 令牌层 → L1 布局框架 → L2 关键页面（登录/仪表盘）→ L3 代表页面（列表/流程中心/个人中心）→ L4 暗色适配。
6. **零业务改动**：仅改样式层（style.css、布局、页面模板 class），不动 script 逻辑与接口。
7. **验证**：构建通过 + 浏览器截图对比（亮/暗、关键页面）+ 关键交互回归（登录、菜单、页签）。

## Open Questions

- 主色 `#1a56db` 的 `industrial` 是否被业务页面直接引用为语义色（如安全相关的 `safety` 琥珀）？—— 需在实现时 grep 确认，避免破坏语义。
- 流程设计器（bpmn-js）与表单设计器（form-create）的深色画布区是否纳入本次美化？—— 默认仅做外壳与表层适配，画布内部不改（防破坏）。
