# 字段权限卡片式设计

- 日期：2026-08-18
- 状态：待用户审阅
- 涉及组件：`frontend/src/views/designer/properties/FormPropertyTab.vue`（节点级字段权限配置）

## 1. 背景与问题

节点级「字段权限」表格当前三列：字段名 / 权限 / 数据来源。数据来源列为嵌套下拉（源类型选择 + 源字段/源节点/源变量选择，垂直堆叠），导致：

1. **每行过高**：数据来源列垂直堆叠 2 个下拉，行高显著增加；
2. **横向滚动**：字段名 + 权限 + 数据来源（170px+）总宽超出属性配置栏（约 300-400px），必须横向滚动，交互不友好；
3. **表格臃肿**：字段多（实测最大表单 11 字段）+ 每行高，整体观感差。

真实使用模式：**多数字段保持默认权限即可，仅少数字段需精调数据来源/特殊权限**。

## 2. 方案迭代

### 2.1 第一轮：紧凑表格 + 行内展开（已实现，效果不佳）

将数据来源列改为行内展开（手风琴），表格压缩为三列（字段名 / 权限 / 映射按钮）。用户实测反馈：**效果很不好**。

### 2.2 第二轮：卡片列表（当前设计，已获用户确认）

经用户确认，改为**卡片列表**：每个字段一张卡片，纵向堆叠；卡头呈现字段名 + 权限下拉 + 映射按钮；点击映射按钮在卡体内展开来源配置区。

- 卡片形式：卡片列表，每字段一张卡，纵向堆叠
- 展开交互：点「映射」按钮展开/收起
- 卡头内容：字段名 + 权限 + 映射（手风琴保留）

## 3. 设计

### 3.1 卡片结构

```
┌────────────────────────────────────────────────┐
│ 金额                    [可编辑 ▼]   映射        │ ← 卡头：字段名 + 权限下拉 + 映射按钮
├────────────────────────────────────────────────┤
│ （展开时出现：来源配置区 source-cell）            │ ← 卡体：v-if="expandedField === field"
└────────────────────────────────────────────────┘
```

每字段一张卡片（`div.field-card`），纵向堆叠，卡间间距 8px。卡片自身样式：边框（`#e4e7ed`）、圆角、内边距 10px。

### 3.2 卡头布局

| 区域 | 内容 | 说明 |
|---|---|---|
| 左侧 | 字段名（`field-label`） | 加粗，flex:1，超长省略号 |
| 右侧 | 权限下拉 + 映射按钮 | 权限下拉固定约 110px；映射按钮固定约 110px |

### 3.3 展开交互（手风琴）

- 点击「映射」按钮 → 该卡片**卡体就地展开**来源配置区（源类型下拉 + 源字段/源节点/源变量选择，复用现有 `source-cell` 逻辑）；再次点击收起
- **手风琴**：展开某卡片时自动收起此前展开的卡片（`expandedField: string | null`），保证属性栏内视图聚焦
- 展开状态：单值 `ref<string | null>`（字段名），切换逻辑 `expandedField = expandedField === field ? null : field`
- 卡体 `@click.stop` 防止冒泡误触发

### 3.4 来源摘要文案（已配置映射的按钮显示）

格式：`← <来源类型中文>.<来源目标>`，按 `dataMappings[field].source` 解析：

| 存储格式 | 摘要显示 |
|---|---|
| `form:initiator` + `sourceField` | `← 发起人表单.姓名` |
| `form:<nodeId>` + `sourceField` | `← 节点.<源字段>`（节点名优先，缺省回退 nodeId） |
| `variable:<name>` | `← 变量.requestAmount` |

- 未配置（source 为空）：按钮显示「映射」（普通样式）
- 超长摘要省略号截断

### 3.5 行为规则

- 未展开的卡片只有一行高度，属性栏内**无需横向滚动**
- 权限默认值不变：选择表单后默认全字段 `EDIT`
- 存储格式不变（`FormFieldDataMapping[]`），仅 UI 层折叠/展开
- 数据来源类型切换（onSourceChange）/节点切换（onNodeChange）/源字段加载逻辑**完全复用现有实现**，仅从"常驻渲染"改为"展开时渲染"

## 4. 实现要点

- `FormPropertyTab.vue`：
  - 模板：`el-table` 替换为 `div.field-card` 卡片列表（`v-for="field in fieldList"`）；卡头 flex 排列字段名 + 权限下拉 + 映射按钮；`source-cell` 从常驻改为 `v-if="expandedField === field.field"` 条件渲染在卡体
  - 脚本：`expandedField = ref<string | null>(null)`、`toggleExpand(field)`、`mappingSummary(field)`、`isMapped(field)` 复用已实现逻辑（本轮零脚本新增，仅模板渲染容器变化）
  - 卡头/卡体/权限下拉均 `:disabled="readOnly"`
- 流程级 `ProcessFormPropertyTab.vue`（两列，无数据来源列）：**不动**，本身已紧凑
- 后端/存储：**零改动**

## 5. 测试策略（TDD）

更新 `frontend/src/views/designer/properties/__tests__/FormPropertyTabs.test.ts`：

**RED→GREEN 顺序：**

1. **锚点迁移**：`.el-table__row` → `.field-card`（expandRow/pickSource 及所有行定位逻辑）
2. **默认不渲染 source-cell**：挂载后所有卡片内无 `.source-cell`
3. **点击展开**：点击某卡「映射」按钮 → 该卡 `.source-cell` 出现
4. **手风琴收起**：点击卡 A 展开 → 点击卡 B 展开 → 卡 A 的 source-cell 消失、卡 B 出现
5. **再点收起**：点击已展开卡的「映射」按钮 → 该卡 source-cell 消失
6. **摘要文案**：
   - 预置 `dataMappings: [{ targetField: 'name', source: 'form:initiator', sourceField: 'name' }]` → 按钮文本含「发起人表单」
   - 预置 `variable:` 来源 → 按钮文本含「变量」
7. **既有回归**：数据来源配置用例改为"先点映射按钮展开，再配置"（锚点改为卡片），断言逻辑不变
