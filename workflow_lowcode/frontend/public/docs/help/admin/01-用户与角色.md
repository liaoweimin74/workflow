# 01 用户与角色

## 1.1 用户管理（系统管理 → 用户管理）

日常操作：

| 操作 | 说明 |
| --- | --- |
| 新增用户 | 填账号、姓名、初始密码、所属机构等基础信息 |
| 分配角色 | 用户列表「角色」列直接维护；权限=多个角色的并集 |
| 启用 / 停用 | 行内切换。停用后该用户无法登录，已有数据不受影响 |
| 重置密码 | 行内操作，二次确认后重置；告知用户新密码并要求自行修改 |

原则建议：

- 账号一人一号，禁止共用；人员离职**停用**而非删除，保留操作痕迹；
- 用户按机构归属，角色管权限——两者分开维护；
- 批量开号时先建好角色，再按角色批量分配。

## 1.2 角色管理（系统管理 → 角色管理）

角色 = 一组菜单 + 按钮权限的打包。

1. 新建角色（如「行政专员」「财务审批」），填名称与备注；
2. 打开角色的**菜单权限树**勾选授权：
   - 目录 → 菜单 → 按钮三级；只勾子级时祖先目录自动补齐；
   - 按钮项决定页面内细粒度操作（如「表单发布」「发送记录重发」）；
3. 保存后让目标用户关联该角色，用户**重新登录**生效。

注意事项：

- 内置超级管理员已默认拥有全部权限，不需要也不应修改它；日常权限请全部经由自建角色下发；
- 挂接了新页面的菜单出现在树里的位置由页面挂接时的「所属目录」决定，找不到时用树的搜索；
- 权限最小化：先给「查询」类按钮，确实需要写操作再逐个放开。

## 1.3 典型授权场景

**给某部门开通一个新业务页面**：开发侧页面已发布并挂接菜单后 → 角色管理找到对应业务角色 → 勾选该菜单（含其按钮项）→ 该角色下的用户重新登录即可见。

**临时给某人开通查看权限**：优先复用已有「查看」类角色；没有就新建一个只含查询权限的角色，事后可整体回收。

**用户反馈看不到功能**：按开发手册 [08 权限与菜单](../dev/08-权限与菜单.md#8.6) 的排障清单走一遍，多数是「角色未勾菜单」或「未重新登录」。
