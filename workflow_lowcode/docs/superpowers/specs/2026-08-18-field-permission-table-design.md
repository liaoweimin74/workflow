# 字段权限卡片式设计

- 日期：2026-08-18
- 状态：待用户审阅
- 涉及组件：`frontend/src/views/designer/properties/FormPropertyTab.vue`（节点级字段权限配置）

## 1. 背景与问题

节点级「字段权限」表格当前三列：字段名 / 权限 / 数据来源。数据来源列为嵌套下拉（源类型选择 + 源字段/源节点/源变量选择，垂直堆叠），导致：

1. **每行过高**：数据来源列垂直堆叠 2 个下拉，行高显著增加；
2. **横向滚动**：字段名 + 权限 + 数据来源（170px+）总宽超出属性配置栏（约 300-400px），必须横向滚动，交互不友好；
3. **表格臃肿**：字段多（实测最大表单 11 字段）+ 每行高，整体观感差。

真实使用模式：**多数字段保持默认权限即可，仅少数字段需精调数据来源/特殊权限**。

## 2. 方案迭代

### 2.1 第一轮：紧凑表格 + 行内展开（已实现，效果不佳）

将数据来源列改为行内展开（手风琴），表格压缩为三列（字段名 / 权限 / 映射按钮）。用户实测反馈：**效果很不好**。

### 2.2 第二轮：卡片列表（已实现，效果不佳）

改为卡片列表：每字段一张卡，纵向堆叠；卡头字段名 + 权限 + 映射按钮；卡体展开来源配置。用户实测反馈：**改用回原始表格**。

### 2.3 第三轮：原始三列表格 + 列宽与文案微调（当前设计，已获用户确认）

**恢复原始三列表格布局**（字段名 / 权限 / 数据来源，数据来源常驻渲染），仅做两处微调：

1. **第二列（权限）宽度缩小**：由 100px 缩至 80px；权限选项文案 `可编辑` → `编辑`
2. **第三列（数据来源）宽度减小**：由 min-width 170px 减至 130px

字段名列保持 min-width 100px。恢复后不再需要 `expandedField / toggleExpand / isMapped / mappingSummary`，卡片/展开相关逻辑整体移除。

## 3. 设计

### 3.1 表格结构（原始三列表格，常驻渲染）

| 列 | 内容 | 宽度 |
|---|---|---|
| 字段名 | 文本 `prop="label"` | min-width 100px |
| 权限 | 权限下拉（编辑/只读/隐藏） | **80px**（原 100px） |
| 数据来源 | 嵌套下拉（源类型 + 源字段/源节点/源变量）常驻渲染 | **min-width 130px**（原 170px） |

数据来源列内容（`source-cell`）为原始实现：源类型下拉（无/发起人表单/指定节点/流程变量）永远可见，按类型级联显示源字段/源节点/源变量选择。

### 3.2 权限文案

权限下拉选项文案调整：

| 值 | 文案 |
|---|---|
| `EDIT` | `编辑`（原 `可编辑`） |
| `VIEW` | `只读` |
| `HIDDEN` | `隐藏` |

### 3.3 行为规则

- 无展开/收起交互：所有来源配置常驻显示（原始行为）
- 权限默认值不变：选择表单后默认全字段 `EDIT`
- 存储格式不变（`FormFieldDataMapping[]`）
- 数据来源类型切换（onSourceChange）/节点切换（onNodeChange）/源字段加载逻辑**完全复用现有实现**

## 4. 实现要点

- `FormPropertyTab.vue`：
  - 模板：恢复 `el-table` 三列（字段名 / 权限 / 数据来源），移除卡片列表、映射按钮、`expandedField` 条件渲染；权限列 `width="80"` 且选项文案改「编辑」；数据来源列 `min-width="130"`
  - 脚本：移除 `expandedField / toggleExpand / isMapped / mappingSummary`（卡片/展开时代产物）；`loadInitiatorFields()` 预加载调用保留（对摘要无影响但幂等，可一并移除——以模板不再引用为准，逐项删除未引用函数）
  - 样式：移除 `.field-card-list / .field-card / .field-card-header / .field-card-actions / .field-label`，恢复 `.source-cell` 原样式
- 流程级 `ProcessFormPropertyTab.vue`（两列）：**不动**
- 后端/存储：**零改动**
