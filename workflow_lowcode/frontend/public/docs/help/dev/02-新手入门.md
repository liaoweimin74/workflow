# 02 新手入门

本章带你从零完成一个最小可用的业务功能：员工填报「设备报修」，管理员在列表页查看和处理。走完这一遍，平台的主干开发流程就都摸过了。

## 2.1 准备：登录与认识工作台

- 拿到平台访问地址和账号（向环境管理员申请；需要「开发管理」相关菜单权限，一般由开发者角色或管理员授予）。

打开地址即见登录页，输入账号密码登录：

![登录页](images/login-page.png)

登录后进入工作台（首页）：顶部是全局工具栏，左侧是**主菜单**——本章所有操作都从这里出发。菜单按角色动态显示，能看到「开发管理」即具备本章操作条件。

![工作台：左侧主菜单 + 首页概览](images/dashboard.png)

> 本地开发环境起服务：后端在项目目录执行 `mvn clean spring-boot:run`（默认 8080 端口），前端执行 `pnpm dev`（默认 3000 端口）。注意修改/删除过 Java 源文件时必须带 `clean`，否则残留的旧 class 会导致启动后报 `NoSuchMethodError`。

## 2.2 第一步：建表单（定义数据）

1. 进入 **开发管理 → 表单列表**，点「新建表单」：

![表单列表](images/form-list.png)

   - 填写表单名称（如「设备报修」）与标识 key；
   - 类型选 **业务表单**（业务表单发布后会生成独立数据表存业务数据；工作流表单是给审批流程填报用的，本例用不到）。
2. 点该表单的「设计」进入表单设计器，从左侧组件面板拖入字段，例如：

   | 组件 | 字段 | 说明 |
   | --- | --- | --- |
   | 自动编号 | 报修单号 | 提交时按「前缀+日期+流水」自动生成，不用手填 |
   | 单行文本输入 | 设备名称 | 必填 |
   | 下拉选择 | 故障类型 | 配置静态选项或绑定字典 |
   | 数值输入 | 期望上门费 | 可选 |
   | 日期选择 | 报修日期 | 默认当前时间 |
   | 多行文本 | 故障描述 | 必填 |

3. 给字段设校验：选中字段后在右侧属性面板勾选「必填」或配置校验规则。
4. 点保存，回到表单列表，点该表单的「发布」。状态从「草稿」变为「已发布」后，平台生成了对应的业务数据表。

**认识设计器布局**：表单设计器 = 左侧组件面板（按「基础组件 / 系统组件 / 子表单组件 / 辅助组件 / 布局组件」分组）+ 中间画布 + 右侧字段属性。这套三栏布局在页面设计器里是一样的。

![表单设计器：左侧组件面板 + 画布 + 右侧字段属性](images/form-designer.png)

## 2.3 第二步：建数据源（让界面能取数）

页面组件不直接连表，而是通过「数据源」取数：

1. 进入 **开发管理 → 数据源管理**，点新建：

![数据源管理列表](images/data-source-list.png)

2. 类型选 **业务表单（FORM）**，选择刚发布的「设备报修」表单；
3. 确认字段清单（列名、类型来自表单 schema），保存并启用。

数据源共有五种类型（FORM / WORKFLOW / SYSTEM / SQL / API），差别见 [04 页面与数据源](04-页面与数据源.md)。本例用不到其余四种。

## 2.4 第三步：搭页面（给用户操作界面）

1. 进入 **开发管理 → 页面列表**，点「新建页面」：填名称与标识；绑定表单为可选项（自定义页面主要靠数据源取数，也可按需绑定已发布表单）。

![页面列表](images/page-list.png)

2. 点「设计」进入页面设计器：
   - 拖入 **数据表格** 组件，在右侧属性里绑定「设备报修数据源」；
   - 配置展示列（勾选报修单号、设备名称、故障类型、报修日期）；
   - 开启操作按钮：新增 / 编辑 / 删除（新增、编辑会以弹窗打开表单）；
   - 拖入 **筛选器** 或勾选列的「可筛选」，让「设备名称」支持模糊查询。

   页面设计器与表单设计器同款三栏布局，长这样（示例为列表 + 详情联动页）：

   ![页面设计器：组件面板 + 画布 + 属性面板](images/page-designer-demo.png)

3. 点「预览」在沙箱中试一下：新增一条报修记录，能出现在表格里，说明链路通了。
4. 回到页面列表，点「发布」。

## 2.5 第四步：挂菜单（给用户入口）

发布后的页面在页面列表点「挂接菜单」（设计器工具栏也有「已挂接 N 个菜单」按钮）：

![挂接到系统菜单弹窗](images/menu-mount.png)

- 填菜单名称（如「设备报修管理」）、选择所属目录（首次可挂到根下，之后可在菜单管理里挪位置）；
- 平台自动创建菜单项，权限标识形如 `page:read:{页面key}`；
- 同一个页面可以挂到多个菜单（多处入口共用一个页面），弹窗里会列出已挂菜单并可解除——上图即「已挂 1 个菜单」的状态，继续挂接会给页面新增一条菜单。

## 2.6 第五步：授权（决定谁能用）

1. 进入 **系统管理 → 角色管理**，找到（或新建）目标角色，如「行政管理员」，点该行的「分配菜单」按钮：

![分配菜单权限：菜单树按目录/页面/按钮三级勾选](images/role-menu.png)

2. 在弹出的菜单权限树里勾选刚挂接的「设备报修管理」菜单（树分三层：目录 → 页面菜单 → 按钮权限项，勾父级子级全选）；
3. 到 **系统管理 → 用户管理**，把使用者账号关联到该角色；
4. 用该用户重新登录：左侧出现菜单即授权生效；看不到时按 [08 权限与菜单](08-权限与菜单.md#8.6) 的排查步骤处理。

## 2.7 小结与自检

至此你完成了：建模（表单）→ 取数（数据源）→ 界面（页面）→ 入口（菜单）→ 准入（角色）。可以自问三个问题检验理解：

1. 为什么页面不直接绑表单而要经过数据源？（数据源统一抽象了五种取数方式，页面组件只认数据源）
2. 用户看不到菜单，可能缺哪一步？（角色未勾选该菜单 / 页面未发布或未挂接）
3. 想给「故障类型」加选项，改动落在哪里？（表单设计器或字典管理，取决于组件用的是静态选项还是字典）

下一步建议：读 [03 表单设计](03-表单设计.md) 与 [04 页面与数据源](04-页面与数据源.md)，然后到「样例页面」菜单下看看别人搭好的成品。
