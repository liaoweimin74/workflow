# 05 流程编排

工作流用于「一张单据按规则走完审批」的场景。入口：**流程管理 → 流程定义**，设计器是标准 BPMN 画布。

## 5.1 一个流程的构成

```
开始事件 → 发起节点 → 审批/办理节点（可多个，用网关分支） → 结束事件
              ↑____________表单字段权限/超时/通知挂在节点上____________↑
```

新建流程 → 进入设计器 → 编排 → 保存草稿 → **部署**（部署后流程中心可发起新版本）。流程有版本管理：重新部署产生新版本，已发起的实例继续按旧版本走。

## 5.2 设计器总览与节点面板

![流程设计器：节点面板 + 画布 + 属性面板](images/process-designer.png)

设计器三段式：左侧**节点面板**（图标分组，拖到画布即建节点）、中间 BPMN 画布（连线即流转顺序）、右侧**属性面板**（选中什么配什么）。上图示例含内嵌子流程与服务任务。

各节点**常见应用场景**：

| 节点 | 用途 | 典型场景 |
| --- | --- | --- |
| 开始/结束事件 | 流程起止 | —— |
| 发起节点 | 发起人填报工作流表单（每流程有且仅有一个） | 差旅报销填单、采购申请 |
| **审批节点** | 人工审批，有**通过/拒绝**语义 | 总监审报销单、财务复核金额 |
| **办理节点** | 人工执行任务，做完流转，无通过/拒绝语义 | 出库、安装、开户等执行环节 |
| 服务任务 | 自动执行，无需人工 | 审批通过后自动写台账、调外部接口、跑逻辑流 |
| 内嵌子流程 | 画布内的子流程容器 | 把「一个阶段的多步骤」框在一起（如「现场实施」含派工→执行→验收） |
| 调用活动 | 调用另一条**已部署**流程 | 多条主流程复用同一条「结算子流程」 |
| 定时边界事件 | 附着在任务上，超时走分支 | 审批 24 小时未处理自动转上级/催办 |
| 错误边界事件 | 捕获服务任务/子流程抛错走兜底 | 调外部接口失败走人工处理分支而非卡死 |
| 排他网关 | 多选一 | 金额 > 1 万走总监，否则经理 |
| 并行网关 | 同时分头走、汇合后继续 | 采购单同时要财务与库房并行确认 |
| 包含网关 | 满足几个走几个 | 按订单内容决定「要开发票」和「要送货」两条是否都走 |

## 5.3 审批节点与办理节点的区别

两个都是人工节点，配置面板长得很像，但语义不同：

| | **审批节点** | **办理节点** |
| --- | --- | --- |
| 语义 | 对单据做**通过 / 拒绝**判断，是决策点 | **执行**一件事，做完点完成即流转，不判断对错 |
| 操作 | 同意、拒绝、退回、转签、加签 | 完成、转派；办理人可配置 auto_pass（无人处理时自动通过） |
| 超时处理 | 提醒 / 转派 / **自动通过 / 自动拒绝**（四选一） | 仅**提醒 / 转派**（escalate），没有「替你决定」的动作 |
| 意见与签名 | 可配「意见必填」（拒绝时/始终）、签名（默认上次/上传/必须） | 无审批意见语义 |
| 退回 | 可配退回模式：从当前节点重走 / 发起人选退回目标 | —— |
| 审批人去重 | 可配：与上一节点同一人自动跳过 / 流程中任意前置节点出现过即跳过 | —— |

**怎么选**：这一步「人要判断」→ 审批节点；这一步「人要干活」→ 办理节点。拿不准时问一句：这个节点有可能「不同意」吗？有可能就用审批节点。

## 5.4 网关与条件路由

三种网关的区别一句话版：

| 网关 | 行为 | 类比 |
| --- | --- | --- |
| **排他网关 XOR** | 多条出线**只走一条**：按连线条件顺序判断，走第一条满足的 | if / else if |
| **并行网关 AND** | 所有出线**同时走**，全部到齐后在汇合处继续（同步栅栏） | 同时开工、全部完工才放行 |
| **包含网关 OR** | 满足几条走几条（至少一条），汇合处等所有**被激活**的分支 | 按需开工，做几条等几条 |

**连线条件**：从节点拉出的顺序流上可配三种条件类型——

1. **无条件**：默认流。排他网关建议给一条出线设默认流，否则所有条件都不满足时流程实例**直接报错挂起**；
2. **表单条件**：可视化配置——选表单字段 + 运算符 + 比较值，不用写表达式（如「金额 > 10000」）；
3. **条件表达式**：UEL 表达式（如 `${amount > 10000 && urgent == true}`），输入框支持从下拉选流程变量补全。

**选型**：分支互斥（走大额就不走小额）用排他；几件事必须都做完才能继续用并行；几件事按需做、可能同时做用包含。

## 5.5 边界事件：任务上的「意外出口」

边界事件**附着在人工任务/服务任务上**（从面板拖到任务节点边缘吸附），任务运行期间触发条件命中就激活，流程改走边界事件的出线。两类：

**定时边界事件**——超时出口：

- 定时设置：`PT{n}M`（分钟）/ `PT{n}H`（小时）/ `PT{n}D`（天），如 `PT24H` = 挂起 24 小时后触发；
- **中断（cancelActivity 开）**：触发后原任务**被终止**，流程只走边界分支——适合「超时自动转派/自动通过」；
- **非中断**：原任务继续，边界分支**并行**跑——适合「超时只催办，审批照常等」。

**错误边界事件**——异常出口：

- 捕获**服务任务或子流程**运行抛出的错误，走兜底分支（人工处理、补偿、告警）；
- **错误代码留空 = 捕获任意错误**；填了代码则只捕获匹配的错误；
- 服务任务的失败策略与它配套：**FAIL_FLOW**（失败终止流程，可被错误边界事件接住）或 **IGNORE_CONTINUE**（失败忽略继续，错误信息写入 `__lastError` 变量供下游判断）；
- 逻辑流节点失败时引擎抛 `LOGIC_FLOW_FAILED`——想兜住「逻辑流跑挂了」的场景，错误边界事件留空代码即可。

**与流程级超时规则的关系**：节点属性里还有超时处理（提醒/转派/通过/拒绝），那是**节点内**的轻量处置；边界事件是**流程级**的分岔——超时后要走另一段流程（催办子流程、升级审批）就用边界事件。两者可叠加：先节点内提醒，再边界事件兜底。

## 5.6 子流程：调用活动 vs 内嵌子流程

| | **调用活动** | **内嵌子流程** |
| --- | --- | --- |
| 内容来源 | 引用另一条**已部署**的流程定义（弹窗里搜索选择） | 画布内的一块容器区域，**双击进入编辑** |
| 复用 | 一处定义、多条主流程复用；子流程升级部署新版本即可全局生效 | 只属于当前主流程，不能被别的流程引用 |
| 版本 | 跟随被调流程的版本管理 | 随主流程一起版本化 |
| 变量 | **输入/输出参数映射**：显式声明传什么进、什么出，隔离最干净 | 也做入参/出参映射，且子流程内的同名变量**遮蔽**外部同名变量，出流程即恢复 |
| 适用 | 通用能力沉淀（结算、通知、风控审查） | 仅本流程用的阶段性分组，提高画布可读性 |

**怎么选**：别的流程也会用 → 调用活动；只是给自己流程「折叠一段」→ 内嵌子流程。

## 5.7 服务任务与逻辑流的衔接

服务任务节点是流程里的「自动执行」环节，类型四选一：**java**（后端 Bean）、**expression**（表达式）、**logicflow**（触发已发布逻辑流）、**http**（直接调 HTTP 接口）。

![服务任务属性面板：服务类型 + 逻辑流入出参映射 + 失败策略](images/service-task-logicflow.png)

- **服务类型**选「调用逻辑流」后，下方出现逻辑流下拉（只列已发布的流）与**入参映射 / 出参映射**：每行左侧填流程变量名、右侧填逻辑流变量名；
- 变量在节点上怎么取、怎么写回，见 [09 章 9.4.4](09-自定义开发.md#9.4.4)；
- 失败策略见 [5.5](#5.5)（FAIL_FLOW / IGNORE_CONTINUE）；可配**异步执行 + 重试**，重试耗尽仍失败按失败策略处理；
- 常见组合：**审批通过 → 服务任务触发逻辑流 → 逻辑流写业务表 + 发通知 + 调外部接口**（逻辑流细节见 [06 逻辑编排](06-逻辑编排.md)）。

## 5.8 审批人设置

审批/办理节点的「审批人设置」页签提供七类来源：

| 来源 | 含义 |
| --- | --- |
| 指定用户 | 固定勾选若干人 |
| 角色 | 授予某角色的所有用户 |
| 发起人自选 | 发起时由发起人从待办人列表里选 |
| 发起人自己 | 回到发起人（如「修改后重提」环节） |
| 表单内用户 | 取表单里「用户选择」组件填的那个人（如部门负责人字段） |
| 流程表达式 | 按表达式解析（高级） |
| 自定义选人函数 | 业务系统注册的取人函数（需开发配合） |

配套选项：

- **多人审批方式**：会签（所有人都同意才过，可设通过比例，100 即全员）/ 或签（任一人同意即过）；
- **发起人可调整审批人**：发起时允许增删该节点待办人；
- **无审批人策略**：解析不到人时的兜底（跳过、转指定用户等，按界面选项配置）。

## 5.9 节点操作权限与高级设置

审批节点可勾选允许的操作：**加签**（临时拉人一起审，节点还可设「必须加签」）、**转签**（把待办转给他人）、**驳回**（退回到指定节点）等。

节点高级设置还包含：**意见必填**（拒绝时/始终）、**签名**（默认上次/上传/必须）、**优先级**（50 普通 / 75 重要 / 100 加急，影响待办列表排序与标识）、**截止时间**（N 小时，配合超时提醒）。催办、超时提醒由流程级配置与消息模块配合（见管理手册 04）。

## 5.10 表单与字段权限

流程绑定的是**工作流表单**（在表单列表建类型=工作流的表单）。节点属性里的表单页签设置各字段的三态权限：`可编辑 / 只读 / 隐藏`——典型用法：发起时填「金额、事由」，财务节点才可编辑「实付金额」，审批人看不到内部备注。

## 5.11 超时处理

三种方式，粒度从细到粗：

1. **节点内超时处理**（审批节点属性）：提醒 / 转派 / 自动通过 / 自动拒绝（办理节点只有前两者）；
2. **定时边界事件**：附着在任务上，超时后流程走独立分支（见 [5.5](#5.5)）；
3. **流程级超时规则**：流程属性中的超时规则对话框，按节点统一配置提醒/处理动作。

## 5.13 常见问题

**Q：部署了新版本，进行中的实例会跟着变吗？**
不会。实例按发起时的版本走完，新版本只影响之后发起的实例。

**Q：会签卡住了怎么办？**
会签要求达到通过比例；等不到某人时，有「转签/加签」权限的审批人或管理员可在待办/流程中心处理，管理员也可在流程运维里干预。

**Q：想按部门总经理审批，人怎么配？**
推荐「表单内用户」：表单里放一个部门/人员字段（可用部门选择组件 + 逻辑流/自定义函数解析主管），节点审批人取该字段；或注册自定义选人函数。

**Q：流程走到排他网关就报错？**
排他网关所有出线条件都不满足且**没设默认流**时实例会报错挂起。给网关补一条无条件默认出线，或放宽条件。

**Q：服务任务调逻辑流失败了，流程直接挂了？**
服务任务失败策略默认 FAIL_FLOW（失败终止）。想不挂：改 IGNORE_CONTINUE 让流程继续（用 `__lastError` 判断），或保持 FAIL_FLOW 并在节点上挂**错误边界事件**（错误代码留空）走兜底分支。
