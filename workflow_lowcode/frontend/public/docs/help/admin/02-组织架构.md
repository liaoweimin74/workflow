# 02 组织架构

三个页面配合：**组织机构**（树）→ **岗位管理**（横向职能）→ **成员组管理**（灵活的临时分组）。

## 2.1 组织机构（系统管理 → 组织机构）

维护公司/部门树：新增下级机构、改名、调整排序与上级、启停。

- 树结构影响用户归属和部分选人组件的展示（表单「部门选择」按此树出选项）；
- 机构撤并时先确认该机构下用户已迁移，再停用/删除空机构；
- 机构编码唯一，建好后不建议改动。

## 2.2 岗位管理（系统管理 → 岗位管理）

横向职能标签（如「项目经理」「出纳」），供业务引用：

- 新增/编辑/启停岗位；
- 岗位与用户的关联在用户/岗位维度维护（按界面提示操作）；
- 典型消费方：流程审批人按角色/岗位解析、SQL 数据源按岗位过滤。

## 2.3 成员组管理（系统管理 → 成员组管理）

成员组是跨机构、跨岗位的**手动维护**分组（自动规则机制已移除），适合「专项小组」「评审专家池」这类人员集合：

- 左栏：成员组的增删改、启停；**删除组会连带移除全部成员关系且不可恢复**，确认提示要认真看；
- 右栏：维护组内成员，可从用户中挑选添加、行内移除。

注意：成员关系是「快照式」的——用户后续调岗/离职不会自动移出成员组，需要管理员定期巡检（建议每月一次核对关键组成员）。

## 2.4 维护节奏建议

| 事项 | 频率 | 动作 |
| --- | --- | --- |
| 人员入职/离职 | 实时 | 用户建号/停用，迁移机构与岗位 |
| 机构调整 | 按需 | 调树，同步相关流程审批人配置 |
| 成员组巡检 | 每月 | 核对成员与实际在职/在岗一致 |
| 角色权限复查 | 每季度 | 按 [01 章](01-用户与角色.md)最小化原则复核授权 |
